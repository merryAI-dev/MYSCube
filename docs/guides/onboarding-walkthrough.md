# Onboarding walkthrough

Product route: `/guides/onboarding`. Existing admin, portal and feature-search entry points open the informational guide in a new tab, preserving any original work. MembershipPending renders the same guide inline without granting access to protected routes. Loading failures retain a way back to the membership status screen.

This is a labeled future-flow prototype, not a released self-service enrollment implementation. Current guidance remains requesting an administrator to link the verified login to the staff record and separately approve roles. No API, role policy, Firestore rule or production record changes are included.

Media is recorded from existing redesigned components with synthetic example.com identities only. The 1280×900 MP4 is 55.083 seconds: 53.086 seconds of timestamped browser frames plus a final hold. Output is 24fps; it is not a native 24fps capture claim. No interpolated UI frames or fabricated cursor paths. Korean captions and a text alternative are included. Primary demonstrations are four real image/gif chapters at original timing: 14 / 20 / 13 / 8.08 seconds, 640×936, 56 / 80 / 52 / 33 frames, total 580,512 bytes. Only horizontal whitespace is cropped; each frame is labeled synthetic. They load lazily, animate by default, and switch to PNG posters on Stop or reduced-motion preference. MP4 is optional in a collapsed disclosure, with controls and no autoplay. The footer 4× preview remains secondary.

Validation: product build; membership/auth/route tests; browser playback, seeking, speed, caption rendering, narrow viewport, FAQ and inline membership return. Reduced-motion CSS is implemented; real-device performance and OS setting tests are not claimed. New enrollment backend persistence remains unimplemented and is explicitly labeled throughout the guide.

The same release applies the approved shared component styling and motion to actual permission management, staff details, membership waiting, and route surfaces. No prototype harness or synthetic API adapter is included in the product. Staff handoff targets `/users?search=...`; filters cannot keep an unrelated hidden action target. The self-service form remains unavailable until a separately approved backend contract exists. Light palette overrides are scoped away from the existing dark theme.

Independent review resolved filtered-target mismatch, stale role-error feedback and dark palette leakage. Browser checks confirmed actual app `/users` navigation and preserved dark shell; isolated current product components rendered the approved list/detail design, disclosure interaction and empty-search removal of action targets. Authenticated production UI remains a separate post-deployment check.
