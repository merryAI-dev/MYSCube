# 현금흐름 시트 연동·주간 정산 Stage QA 시나리오

**기준일:** 2026-07-27  
**대상:** Stage만 (`inner-platform-internal-stage`)  
**범위:** 시트 연결 → 명시적 값 불러오기 → 현금흐름 표시 → 주간 정산. 월 결산 확정·재오픈은 다음 QA 묶음에서 다룬다.

## 현재 제품 계약

- Google Sheet의 **표시값(value)** 이 원본이다. MYSCube는 수식을 재계산하거나 Sheet로 되쓰지 않는다.
- `null`/빈 셀은 **미입력**, 명시적 `0`은 **0원**으로 구분한다.
- 시트 반영은 사용자가 `시트 값 불러오기`를 누를 때만 수행한다. 자동 동기화는 없다.
- 주간 정산은 목요일 자정 준수 여부를 기록·표시하는 운영 신호다. **월 결산 전에는 정산된 주차도 값 변경을 막지 않는다.** 시트 반영값이 주간 정산 기준과 다르면 경고와 이력만 남긴다.
- 월 결산이 완료된 월만 서버 스냅샷으로 고정한다. 월 결산 이후 변경은 별도 재오픈 계약의 범위다.
- 화면은 계산 권한이 없다. BFF는 조합·조회, Spring JVM은 원장 반영·상태·감사 이력의 최종 권한을 가진다.

## 공통 준비

1. Stage 프로젝트 하나에 `cashflow(사용내역 연동)` 탭을 연결한다.
2. 동일한 시트의 사본을 만들고, 한 셀을 **빈 값**, 한 셀을 **0**, 한 셀을 **금액**으로 준비한다. 원본은 수정하지 않는다.
3. Stage의 `테스트 날짜와 시간`을 사용할 경우, 실제 서버 시각이나 운영 데이터에는 영향이 없음을 먼저 확인한다.
4. 브라우저 개발자 도구 Network/Console을 열고, 요청 ID와 `cashflow_transaction` 로그를 보관한다.

## 중단·판정 규칙

- `미입력`과 `0`이 하나라도 합쳐지면 **실패**다.
- 시트에서 값을 바꿨는데 명시적 불러오기 후에도 그대로이거나, 값은 바뀌었는데 이력이 남지 않으면 **실패**다.
- 주간 정산이 월 결산 전 값을 409/잠금으로 막으면 **실패**다. 이는 주간 신호와 월 고정을 혼동한 회귀다.
- 월 결산 완료 월의 변경 허용 여부는 이 문서에서 판정하지 않는다. 별도 월 결산·재오픈 QA로 넘긴다.
- `SHEET_CONTROL_TOTAL_MISMATCH`는 시트 값 손상을 찾는 검토 신호다. 주간 정산 전 반영을 막거나 값을 자동 보정하면 **실패**다.
