# 정산 에이전트: 검증 가능한 이진 피드백 정책

문서 상태: 초기 수학·구현 기록. 아래의 미연결/고정 renderer 서술은 당시 상태이며 현재 운영 상태의 단일 기준이 아니다. 후속 구현 이력과 PLC-DPO 외부 궤적 선택기 제안은 [연구 초안 §3·8](2026-09-14-evidence-grounded-agent-paper.md)을 참조한다. 이 문서의 스칼라 피드백 학습을 Gemini 또는 PLC-DPO 학습으로 해석하지 않는다.

## 구현과 운영 경계

`server/mcp/settlement-feedback.mjs`는 단일 조회 해석에 대한 검토된
이진 피드백을 학습한다. `settlement-agent.mjs`가 도구 실행 전에 호출한다.
Gemini 내부 weight, temperature 또는 정산 DB 값은 변경하지 않는다.
도구 선택은 여전히 LLM 제안이다. 결정적인 것은 입력 검증, 피드백 정책,
도구 실행 계약과 서버 결과 렌더링이며 자연어 해석 자체가 결정적이라는 뜻은 아니다.

Slack ingress는 현재 질문을 큐에 저장할 뿐이다. 실제 Slack 피드백 수집,
Firestore 피드백 저장/읽기, 사용자 연결, 실행 워커는 아직 연결되지 않았다.
따라서 현재 결과는 라이브러리 구현이며 운영 학습 완료가 아니다.

## 목적함수와 해법

동일 질문·도구·조회 범위에 속하는 검토된 라벨을 y_i ∈ {0,1}로 둔다.
1은 질문에 맞는 조회 범위, 0은 잘못 해석한 범위다. 일반적인 “도움 안 됨”은
이 라벨과 다르므로 자동 변환하지 않는다. 승인된 host가 의미를 구분해야 한다.

각 범위의 스칼라 weight w에 대해 p=σ(w), λ=1, prior w₀=0:

    J(w) = mean[log(1+exp(w)) − y_i w] + λ/2 · w²
    J′(w) = σ(w) − mean(y) + λw
    J″(w) = σ(w)(1−σ(w)) + λ ≥ 1

강볼록이므로 유일한 최적점이 존재한다. J′(-1)<0, J′(1)>0이므로
[-1,1]에서 60회 이분법으로 근을 구한다. gradient 잔차도 반환한다.
softplus는 overflow를 피하는 max(w,0)+log1p(exp(-abs(w)))로 계산한다.
라벨이 없으면 중립 w=0,p=0.5이며 정확도 50%라는 실측 주장이 아니다.

p<0.5이면 범위를 다시 확인한다. 최적점의 부호는 mean(y)-0.5와 같으므로
경계 판단은 mean(y)<0.5로 계산해 수치 흔들림을 피한다.
이 경계에서는 L2가 weight 크기를 줄이지만 다수결 방향은 바꾸지 않는다.
평균 손실이므로 동일 비율의 표본이 늘어도 점수는 같다. 신뢰구간이나
실제 정답 확률, 범위 간 일반화를 제공하는 모델이라고 주장하지 않는다.

## 실행·감사 계약

- 모델에 없는 host 전용 `loadFeedback(scope)`가 검토된 표본을 제공한다.
  host는 tenant/user를 자신의 인증 컨텍스트에 묶어야 한다.
- scope는 질문(trim), 도구 이름, schema 검증 후 입력을 포함하며 projectIds는 정렬한다.
  새로운 도구는 필요 시 자신의 입력 정규화 계약을 추가해야 한다.
- 같은 ID의 동일 라벨은 중복 제거, 충돌 라벨은 거부한다. Slack 반응 변경은
  host가 최신 검토 revision으로 정리해야 하며 원시 이벤트를 누적 투입하면 안 된다.
- 알고리즘 버전, 데이터 해시, 표본 수, weight, loss, gradient를 record에 전달한다.
  record의 영속 저장과 append-only 권한은 아직 host의 미구현 책임이다.
- 부정 피드백은 확인 요청만 유도한다. host의 `isScopeConfirmed(scope)`가
  해당 범위의 명시적 확인을 증명하면 기존 권한 검증을 거쳐 재조회한다.
- 사실 답변은 code renderer만 생성한다. 모델이 “999개 완료”라고 바꿔도 사용하지 않는다.
  현재 도구에는 서버 집계 count가 없으므로 완료 개수를 만들어 답하지 않는다.
- 일부 조회 실패는 partial로 남는다. 월결산 상태는 JVM의 cycle.businessState와
  health를 사용하며 오래된 월 상태나 원시 시트로 역산하지 않는다.

## 논문과의 정확한 관계

[DPO 본문 §3–4, 식 1–7](https://arxiv.org/html/2305.18290v3)은
답변 쌍의 선호와 정책 확률비를 사용한다. 단일 yes/no에는 답변 쌍이 없고,
Gemini API는 여기서 학습할 모델 파라미터가 아니므로 본 구현을 DPO라고 부르지 않는다.
여기서는 Bernoulli likelihood의 표준 BCE와 명시적인 L2 항을 사용했다.
DPO의 KL 제약과 L2는 서로 다른 정규화다.

[Reflexion 본문 §3, Algorithm 1](https://arxiv.org/html/2303.11366v4)은
언어적 반성과 episodic memory를 사용한다. 그 방식만으로 수치 재현이나
사실 정확성이 보장되지는 않으므로 본 구현의 사실 경계로 사용하지 않았다.

자기회귀 모델의 p(y|x)=∏ p(y_t|x,y_<t)는 문장의 생성 확률이지
DB 사실의 증명이 아니다. 사실은 검증된 서버 응답에서 코드로 표시한다.
