# 정산 ReAct 에이전트: 클라우드 실행 계약

후속 방향과 2026-09-14 배포 중단 기록은 [증거 기반 에이전트 연구 초안](2026-09-14-evidence-grounded-agent-paper.md)을 참조한다. 아래 내용은 초기 설계 이력이며 후속 설계의 구현 완료를 뜻하지 않는다.

상태: **초기 설계 기록(현행 구현 아님)**. 아래 Cloud Run·DM·자동 공지·취소·세션 재개 항목은 구현을 보장하지 않는다. 실제 배치·권한·검증·한계는 [운영 계약](../operations/settlement-agent.md)을 따른다.

## 근거와 선택

2026-09-14 확인한 공식 릴리스는 Hermes Agent v0.21.2 (v2026.9.11), OpenClaw v2026.9.4다. 사용자 표현인 Hermes2/OpenClaw2와 동일한 별도 제품인지는 확인되지 않았다.

- https://github.com/NousResearch/hermes-agent/releases — 세션 저장 동시 쓰기와 프로필 간 데이터·비밀값 격리 수정. 작업 상태를 컨테이너 로컬 파일에 두지 않으며 모든 키에 tenant와 주체를 포함한다.
- https://github.com/openclaw/openclaw/releases — 도구 확장 시 capability 검토, 세션 접근 범위, Slack 상태·중단·Block Kit 개선. 도구 등록은 배포된 allowlist로 제한하고 사용자별 세션을 기본으로 한다.

기존 `server/mcp/cashflow-status.mjs`의 권한 적용 BFF 조회와 응답 검증을 재사용한다. `server/mcp/server.mjs`는 stdio와 로컬 OAuth launcher에 의존하므로 클라우드 서비스로 그대로 배포하지 않는다. 범용 에이전트 전체 설치 대신 이 계약을 구현하는 작은 ReAct 실행기를 채택한다. Hermes/OpenClaw 연동은 이후 같은 조회 도구 계약의 별도 클라이언트로 추가할 수 있다.

## 배치

Slack HTTPS ingress → 영속 작업 등록 → 큐 → Cloud Run worker → 모델/tool loop → BFF → JVM.
Cloud Scheduler → 정기 조회 작업 → 같은 큐.
Firestore: 작업, 세션, 실행 단계, 발송 이력. Secret Manager: 모델·Slack 비밀값.

노트북·로컬 OAuth 브라우저·로컬 cron·컨테이너 파일은 운영 의존성이 아니다. 요청 기반 worker는 큐의 인증된 HTTP 요청 안에서 실행한다. 응답을 먼저 반환하고 백그라운드 Promise를 남기지 않는다. 인스턴스 종료 후 미완료 작업은 큐 재전달로 복구한다.

## 도구와 권한

도구 계약: name, version, inputSchema, outputSchema, requiredScopes, effect(read/write), timeout, handler.
모델에는 현재 사용자에게 허용된 도구 정의만 전달하고 실행 직전에도 서버가 검사한다. 등록되지 않은 도구, 임의 URL, 임의 SQL, shell 실행은 제공하지 않는다. 미래 쓰기 도구는 별도 승인된 명령·입력 hash·만료시각·승인자에 결합된 실행 승인과 idempotency를 요구한다.

초기 기능: 사용자 조회 범위, 프로젝트 검색, 주·월 정산 상태, 승인 이력, 검증 문제·해결법, 체크아웃 상태 조회. 기존 `cashflow_status`는 프로젝트 ID를 요구하므로 권한 내 프로젝트 검색 경로를 먼저 연결해야 한다. 새 도구 이름만 선언하고 handler 없이 노출하지 않는다.

Slack team_id/user_id를 검증된 MYSCube 구성원과 서버에서 연결한다. Slack 본문의 tenant·role·email은 권한 근거로 쓰지 않는다. 로컬 OAuth 토큰이나 개인 관리자 토큰을 공용 서비스 토큰으로 복제하지 않는다. BFF가 위임 사용자와 서비스 주체를 함께 검증하도록 인증 경로를 구현한다. 계정 연결 해제와 권한 변경은 다음 도구 호출에 반영한다.

상태·마감·대상 제외는 기존 BFF/JVM 판정을 사용한다. 승인 여부를 Slack 대화나 모델 기억에서 추정하지 않는다. 월결산 대상월과 운영 주기월은 기존 응답의 별도 필드를 유지한다. 조직장 체크아웃 승인 후 현재 정산 대상 제외, 과거 이력 유지 여부를 웹과 함께 검증한다.

## ReAct 실행과 영속성

작업 상태: queued → running → succeeded / failed / cancelled. worker는 transaction으로 lease와 fencing token을 획득한다. 만료된 lease의 이전 worker가 결과나 발송 상태를 덮어쓸 수 없다. 한 사용자·스레드의 동시 질의는 순서를 유지하고 다른 사용자의 비공개 도구 결과를 다음 질의에 포함하지 않는다.

질문 → 모델 도구 요청 → schema 검사 → 권한 검사 → 도구 실행 → 결과 저장 → 추가 조회 또는 답변. 최대 단계·시간·출력 토큰·응답 크기를 제한한다. 제한 도달 시 미확인 범위를 명시한다. 모델 장애와 조회 장애를 미승인 상태로 표현하지 않는다. 취소는 다음 호출과 발송 전에 확인한다.

완료된 도구 결과와 응답 초안을 저장하여 재시작 시 불필요한 호출을 줄인다. 재사용 결과는 출처 시각을 표시하고 권한을 재검증한다. 최신 여부가 필요한 상태는 재조회한다. 내부 추론 원문은 저장하지 않고 도구 이름·결과 코드·근거·소요·토큰 사용량을 감사한다.

## Slack 전달

서명과 timestamp를 검증하고 승인된 workspace의 이벤트만 받는다. event_id로 중복 작업을 차단한다. 영속 등록 실패 시 성공 ACK를 보내지 않는다. Slack 응답 제한 시간 내 ACK하고 worker가 후속 응답한다. 자체 bot 이벤트와 중복 재전달은 새 실행을 만들지 않는다.

개인 권한으로 조회한 결과는 기본 DM으로 전달한다. 채널 공지에는 지정된 채널 수신자 범위에 허용된 사업만 넣는다. 스레드가 같다고 구성원별 권한이 같은 것으로 간주하지 않는다.

응답에는 대상 기간, 조회 범위, 조회 시각, 확인 불가 건, 웹 상세 링크를 포함한다. 정기 공지는 승인된 schedule/channel에 한해 발송한다. 발송 직전 현재 상태를 재확인한다. Slack 전송 성공 후 DB 저장 실패 시 무조건 재발송하지 않고 delivery_unknown으로 남겨 전달 여부를 조정한다. 외부 전송의 exactly-once를 보장한다고 주장하지 않는다.

## 오류 안내 공유

앞서 요청된 웹 오류창과 Slack 모두 같은 검증 issue를 사용한다. sourceCell, 확인된 수신 상태, 가능한 원인, 수정 단계, 재불러오기 절차를 제공한다. EMPTY만으로 수식 부재나 실제 0을 단정하지 않는다. 회계 서식 문제에는 0 표시 서식 `#,##0;-#,##0;0`을 조건부 안내한다. 미확인 오류에는 문의용 requestId를 표시한다. 모델이 수식이나 재무값을 수정하지 않는다.

## 수용 시험

1. 같은 사용자·기간으로 웹과 도구의 상태·대상월·대상 사업이 일치한다.
2. 자연어 질문에서 프로젝트 검색 후 상태·문제를 추가 조회하는 실제 다단계 호출을 검증한다.
3. 사용자 A의 도구 결과를 B가 같은 채널에서 조회할 수 없다. 위조 tenant·등록 외 도구·도구 결과의 악성 지시가 권한을 넓히지 못한다.
4. 이벤트 중복, lease 만료, 단계 중 worker 강제 종료 후 작업이 유실되지 않는다.
5. 모델 timeout, BFF 장애, 부분 조회 실패, Slack 429, 발송 결과 불명확을 구분한다.
6. 체크아웃 승인된 사업이 다음 정기 조회에서 제외되고 과거 이력은 유지된다.
7. 실제 연결 모델의 tool calling을 검증하고 실제 Slack 테스트 workspace에서 질의·DM·취소를 확인한다.
8. 노트북을 종료한 상태에서 예약 점검과 새 질문 응답을 확인한다.

- Slack 채널 `C0BQ6980HR6` (`0_전사_공지_08_myscube`). 기존 알림 앱 재사용을 우선한다. 코드에는 기존 `SLACK_ALERT_BOT_TOKEN` fallback과 주정산 digest가 있다. 앱 표시명은 auth.test 결과로 확인해야 한다.

- 현재 CLI 활성 계정 `ai@mysc.co.kr`의 재인증이 필요하다. 운영 토큰 조회·Firestore 접속·Slack 실발송은 아직 확인하지 못했다.

## 운영 연결 전 확정값

- 모델 제공자·정확한 API 모델 ID (`gpt-luna`는 현재 사용자 지정명), 월 비용 한도, 모델로 전송 가능한 정산 데이터 범위.
- Slack 설치 workspace, 개인 응답 방식, 자동 공지 채널과 시간.
- 기존 GCP 프로젝트 사용 여부, 신규 리소스 비용 승인, 서비스 계정의 최소 권한.

배포는 저장소의 CI 성공 기반 경로를 사용한다. 비밀값은 저장소에 넣지 않는다. 실행 장애 시 예약 작업을 중단하고 읽기 전용 웹 조회로 복귀할 수 있어야 한다. 위 실제 연결 시험 전에는 운영 완료로 보고하지 않는다.
