# 시트 수정 안내 설계 — 구성원이 시트에서 무엇을 고칠지 알 수 있게

**날짜:** 2026-09-30
**상태:** 설계 제안 · 구현 전 · **AI 기능 제외 (2026-09-30 결정)**
**관련:** [주정산·월결산 검사 범위 격리 계획](./2026-09-30-settlement-validation-scope-plan.md) · [시트 오류 확인 흐름 설계](./2026-09-30-sheet-issue-confirm-flow-design.md)

## 1. 목표

경고를 본 구성원이 **시트의 어느 칸을, 무엇으로, 왜** 고쳐야 하는지 바로 알 수 있게 한다. 안내는 전부 **규칙으로** 만든다.

**AI를 쓰지 않는 이유 (결정):** 필요한 정보는 대부분 서버가 이미 가진 오류 상세(셀 주소, 원문, 검산값)와 로그에 있다. AI 설명을 덧붙이면 같은 오류에 문구가 매번 달라지고, 틀린 추정이 섞여 혼란이 커질 수 있다.

## 2. 지금 상태 [확인]

| 항목 | 지금 |
|---|---|
| 안내 생성 | 화면 `cashflow-month-close-blocker-helpers.ts`가 서버가 준 `details`를 한 줄로 옮김 |
| 안내 수준 | "AB17 칸 · 인건비이(가) 숫자가 아니에요 (지금 값: 미정)" |
| 없는 것 | 어느 탭·어느 주차·어느 항목인지 사람 말로, 무엇으로 바꾸면 되는지, 고치면 무엇이 풀리는지, 여러 건을 원인별로 묶기, 시트로 바로 가는 링크 |
| 적용 범위 | 월결산 일부 코드(`SHEET_VALUE_INVALID`, 검산, 합계 불일치). 주정산, 시트 반영 단계는 한 줄 메시지만 |

## 3. 원칙

1. **서버가 가진 사실만 쓴다.** 셀 주소, 원문, 검산값, 범위 판정 결과를 사람이 읽는 문장으로 옮긴다. 추정하지 않는다.
2. **같은 오류에는 항상 같은 안내가 나온다.** 문구는 정책 파일 하나에 둔다.
3. **숫자는 서버가 계산한다.** 불일치 차이는 `reported`와 `computed`로 계산해 보여 준다.
4. **판정 경로 밖에 있다.** 안내를 만들다 실패해도 주정산·월결산 흐름은 영향받지 않는다. 안내가 없으면 지금의 한 줄 메시지가 그대로 나온다.

## 4. 안내 카드

### 4.1 카드 한 장의 구성

| 칸 | 내용 | 출처 |
|---|---|---|
| 어디 | `cashflow(사용내역 연동)` 탭 · **AB17** · Projection · 인건비 · 2026년 5월 2주차 | 셀 주소 + 좌표 계약(`LINE_ROWS`, 주차 열) + 미러의 탭 이름 |
| 지금 값 | `미정` | 이슈의 `rawValue` |
| 무엇이 문제 | 금액 칸에 글자가 있어 읽을 수 없습니다 | 코드별 안내 표 |
| 이렇게 고치세요 | 금액이 정해졌으면 숫자만(쉼표 가능), 아직 없으면 **빈칸**으로 두세요. 0은 "금액이 0원으로 확정"이라는 뜻이라 빈칸과 다릅니다 | 코드별 안내 표 (좌표 계약의 EMPTY/ZERO 구분 반영) |
| 고치면 | 이 칸 때문에 막힌 2026년 5월 반영과 5월 결산이 풀립니다 | 범위 판정 결과 |
| 이번 처리와의 관계 | **범위 안**(지금 막고 있음) 또는 **범위 밖**(지금 처리에는 영향 없음, 해당 월 처리 때 필요) | 범위 격리 계획 |
| 시트로 가기 | 해당 셀 링크 | 스프레드시트 ID + 탭 gid + `range=AB17` [확인 필요: 미러에 gid가 있는지] |

### 4.2 코드별 안내 표

안내 문구는 정책 파일 하나에 둔다(예: `policies/cashflow-sheet-issue-guidance.json`). 코드 곳곳에 문장을 흩어 두지 않는다. 범위 격리 계획의 심각도 분류와 같은 파일로 합칠 수 있다.

| 오류 | 무엇이 문제 | 이렇게 고치세요 |
|---|---|---|
| 금액 칸에 글자·기호 (`sheet_value_invalid`) | 숫자로 읽을 수 없음 | 숫자만 입력, 미정이면 빈칸. "원", 공백, 메모는 옆 메모 칸으로 |
| 금액이 소수·음수 (허용 안 되는 칸) | 원 단위 정수가 아님 | 원 단위 정수로. 환불·차감은 해당 출금 항목에 |
| 스프레드시트 오류값 (`#REF!`, `#VALUE!` 등) | 수식이 깨짐 | 수식이 가리키는 범위를 확인. 행·열을 지우거나 옮긴 뒤 생기는 경우가 많음 |
| 합계 칸 비어 있음 (`control_total_missing`) | 검산할 합계가 없음 | 합계 칸의 원래 수식을 복원 (양식 원본 기준) |
| 주차 합계·잔액이 항목 합과 다름 (`SHEET_CALCULATION_MISMATCH`) | 시트 합계 = X, 항목 합 = Y, 차이 Z | 합계 수식 범위가 모든 항목 행을 포함하는지, 항목 중 글자로 들어간 숫자가 없는지 확인 |
| 전체 합계(`BS`)와 주차 합이 다름 | 같은 방식 | 합계 수식이 `C:BR` 전체를 더하는지 확인 |
| 주차 헤더 형식 (`cashflow_week_header_invalid`) | 주차 표기 규칙 위반 | `26-1-1` 형식으로 |
| 양식 불일치 (`cashflow_sheet_template_mismatch`) | 전사 양식과 행·열 배치가 다름 | 행·열을 추가·삭제하지 말고 양식 원본 위치로 되돌리기. 이 경우는 고치기 전까지 반영 불가 |
| 입금 예정 영역(7~9행) 형식 | 표시용 값을 읽지 못함 (결산에는 영향 없음) | 날짜는 `2026-05-12` 형식, 금액은 숫자 |

**숫자는 서버가 계산해서 보여 준다.** 불일치 차이(Z)는 서버가 이미 가진 `reported`와 `computed`로 계산한다.

### 4.3 여러 건 묶기 (규칙으로 가능한 만큼)

같은 코드 + 같은 항목 + 같은 원문이 여러 주차에 반복되면 한 장으로 묶는다. 예: **"Projection · 인건비 · 5월 1~5주 모두 '미정' (AB16:AF16)"**. 규칙으로 묶을 수 없는 원인 추정(예: "합계 수식 범위가 한 행 짧아 보임")은 하지 않는다. 대신 확인할 곳(합계 수식 범위)을 안내 표에서 짚어 준다.

## 5. 적용 범위

| 화면 | 적용 |
|---|---|
| 월결산 요청 화면 (차단·경고·범위 밖) | 카드 |
| 주정산 완료 (Projection 16주 누락, 범위 밖 주차 문서) | 카드 |
| 시트 반영 검토 (월 제외, 양식 불일치) | 카드 |
| Slack 알림 | 요약 1줄 + 화면 링크 |

## 6. 다른 경로에 영향이 없도록

- 안내는 **응답에 필드를 추가**만 한다(`guidance` 카드 목록). 기존 `blockers`, `warnings`의 모양과 코드는 그대로다.
- `sheetFacts` 저장 모양을 바꾸지 않는다. 카드는 읽을 때 만든다. 그래서 미러 리비전과 결산 증거 해시에 영향이 없다.
- 새 컬렉션을 만들지 않는다. 카드는 응답을 만들 때 계산하고 저장하지 않는다.
- Sheet Lab 동결 영역의 추출·병합 로직은 건드리지 않는다. 필요한 정보(탭 이름, 셀 주소)는 이미 미러에 있다.

## 7. 단계

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 | 안내 표(정책 파일)와 카드 생성 함수(BFF), 단위 테스트 | 동작 변경 없음. 카드를 응답에 추가만 |
| 2 | 화면을 카드 형식으로 교체, 여러 건 묶기, 시트 링크 | 기존 한 줄 안내는 대체 |
| 3 | 주정산·시트 반영 화면에 같은 카드 적용 | 범위 격리 계획 3·4단계와 함께 |
| 4 | 오류 로그(`client_error_events`, BFF 로그)를 보고 안내 표에 없는 코드와 자주 나오는 오류의 문구 보강 | 어떤 오류가 안내 없이 한 줄로 끝나는지가 보강 대상 |

## 8. 검증

| 시나리오 | 기대 |
|---|---|
| 한 칸에 "미정" | 카드: 탭·셀·항목·주차·원문·고치는 법·고치면 풀리는 것 |
| 5주 연속 "미정" | 한 장으로 묶임 (`AB16:AF16`) |
| 합계 불일치 | 시트 값, 항목 합, 차이가 규칙 층 숫자로 표시 |
| 안내 표에 없는 오류 코드 | 지금의 한 줄 메시지가 그대로 나옴 (빈 카드 없음) |
| 시트를 고친 뒤 다시 열기 | 해당 카드 사라짐 |
| 이슈 없음 | 카드 없음, 응답은 지금과 동일 |

## 9. 결정이 필요한 것

1. 안내 표 문구의 최종 검수자 (재무팀).
2. 범위 밖 경고를 전부 보일지, 요약 + 펼치기로 보일지 (범위 격리 계획과 같은 결정).

## 10. 확인하지 못한 것

- 미러에 시트 탭의 gid가 저장돼 있는지 (셀 바로가기 링크에 필요).
- 주정산·시트 반영 화면이 지금 오류 `details`를 받아서 버리는지, 아예 받지 않는지.
- 스프레드시트 오류값(`#REF!` 등)이 지금 어떤 코드로 분류되는지.
