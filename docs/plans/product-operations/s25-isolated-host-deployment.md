# S25 — 독립 AXR 운영 배포

사용자는 2026-09-28에 AXR 전용 CI 배포 권한 연결과 배포를 별도로 승인했다. 이 변경은 기존 PR819를 main에 합치거나 일반 Production/JVM/Hermes 배포를 실행하지 않는다.

## 실행 경계

- GitHub Actions의 `AXR Dedicated Host Deploy`만 전용 VM `myscube-axr-prod-20260924 / asia-northeast3-a / axr-workbench-01`을 갱신한다. 로컬 운영 배포는 사용하지 않는다.
- 신뢰 조건은 저장소 ID `1157869653`, 소유자 ID `240824326`, 승인된 feature branch의 push 이벤트와 정확한 워크플로 경로다. 장기 서비스 계정 키를 발급하지 않는다.
- 기존 `axr-deployer`에 해당 VM의 OS Admin Login, AXR 프로젝트의 호스트 메타데이터 읽기, `10.81.0.2:22`만 허용하는 IAP 접근, VM 실행 계정에 대한 Service Account User를 연결했다. sudo 가능한 배포 계정은 AXR 호스트 전체에 영향을 줄 수 있으며, 원본 업무 프로젝트의 IAM은 변경하지 않는다.
- `CI`와 `Workbench CI`의 승인 브랜치 push 실행이 모두 성공해야 클라우드 자격 증명을 사용한다. PR의 임시 병합 커밋 성공으로 대체하지 않는다. 기존 세 운영 배포 워크플로의 `main` 필터는 유지한다.
- 앱과 렌더러는 동일한 소스 SHA로 production_candidate 빌드한다. 기존 브라우저 Firebase 설정의 해시를 대조하며 모델 키와 운영 환경 파일은 CI로 복사하지 않는다.

## 저장 자료와 복구

기존 `0dc6`는 신규 workspace 페이지를 읽지 못한다. 새 버전에서 저장한 뒤 구버전을 재시작하는 자동 롤백은 허용하지 않는다. DB를 과거 시점으로 되돌리지 않는다.

업그레이드는 새 릴리스를 먼저 검증한 뒤 AXR만 점검 상태로 전환한다. 교체 중 자동 부팅을 막고 앱·렌더러·설치 영수증을 함께 갱신한다. 실제 호스트의 컴파일·합성 SQL·렌더러 격리 검사와 로컬 정적 파일·401 검증이 통과해야 공개한다. 실패하면 AXR을 점검 상태로 유지하고 원인과 설치 단계를 보존한다. 복구는 기록을 보존하는 호환 버전의 전진 배포로 진행한다.

이 절차는 기존 MYSCube, 원본 업무 데이터, 주정산·월결산 코드, 복사 작업과 예약 주기를 변경하지 않는다. 성공 이후에도 실제 사용자 SSO·업무 질의 정확도와 성능 목표는 별도 수용 항목이다. 기존 80/100 평가를 배포 성공만으로 올리지 않는다.

## 배포 증거

실행 전 점검에서 기존 AXR 서비스 active, 현재 설치 경로 `0dc6fe797713043a7bdb747b6a2eb9da14da082c`, 운영 설정·nginx·설치 영수증 해시와 이미지 ID를 직접 읽었다. 기존 CI `36367946418`과 Workbench CI `36367946417`은 성공했으나 PR 기반 검사이므로 새 배포의 exact-source push CI를 별도로 실행한다.

2026-09-28 12:23 KST에 소스 `93d138186bf1c2459b86343f00e213174a0de8d5`의 독립 AXR 배포가 완료됐다. 아래 결과는 실제 운영 확인이다.

사전 검증: 업그레이드·초기 설치·TLS 관련 75/75, exact-source CI 승인/거부 독립 반증 7/7, JavaScript·YAML·실행 셸 구문 검사를 통과했다. 실제 VM은 base systemd unit 3개가 기존 릴리스와 일치하고, 앱의 역방향 의존성은 `multi-user.target`만 있으며 nginx도 AXR 한 사이트뿐임을 읽기 전용으로 확인했다. 이 결과는 실제 배포 실행 성공을 대신하지 않는다.

첫 실행 `36370729012`는 소스 `2c1a01baecfd3f8e7658b5bef2b938b230547646`의 CI 두 개(Workbench 1,208개 테스트·84개 브라우저 검사 포함), 실제 운영용 이미지 검사와 WIF 인증을 통과했다. 그러나 IAP SCP 전송에서 약 4분간 41MB만 전달돼 앱 교체 전에 취소했다. 기존 앱과 데이터는 유지됐다.

대용량 이미지 묶음은 VM이 같은 리전의 고정 비공개 GCS 경로에서 직접 받도록 바꿨다. CI의 단기 배포 토큰은 SSH 표준입력으로만 전달하고 파일·환경변수·명령 인자에 저장하지 않는다. 새 IAM 권한은 추가하지 않는다. 작은 검증 코드 압축 파일만 IAP로 전달하며 실행 전 SHA256을 확인한다. 다운로드에서도 외부에서 고정한 manifest 해시, 개별 파일 크기·해시, 소스·플랫폼·분류를 검사하고 기존 JS 전체 검증기를 다시 통과해야 설치할 수 있다. 실제 SSH 표준입력 전달은 비밀값 없는 표식으로 확인했다.
