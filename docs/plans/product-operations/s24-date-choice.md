# S24 1단계 — 사용자가 선택한 날짜 기준을 조회에 연결

2026-09-28 첫 단계 구현·검증 완료, 운영 미배포. 이 단계는 서버가 발급한 날짜 선택을 실제 조회까지 유지하는 변경이다. 모든 자연어 모호함이나 누락 집계를 자동으로 해결했다는 의미는 아니다.

## 사용자에게 달라지는 점

날짜 기준 확인이 필요한 경우 현재 자료에 있는 ‘계약 시작일’, ‘계약 종료일’ 등을 버튼으로 선택한다. 선택 기준은 대화 상단에 표시되고 새로고침이나 조회 실패 후에도 유지된다. 같은 자료의 기간만 바꾸면 선택한 날짜 항목을 유지한다. React 제작 화면과 기존 HTML 대화에 동일하게 적용한다.

모델이 선택과 다른 날짜 조건을 만들면 조회를 실행하지 않고, AI가 만든 조건이 다르다는 이유와 선택 보존·재조회 방법을 안내한다. 버튼 문구를 입력창에 쓰는 것만으로는 선택 완료 처리하지 않는다. 자료 항목이 바뀌면 기존 선택을 그대로 적용하지 않고 재선택 안내를 표시한다. 답변 옆 날짜 기준은 실제 해당 기준으로 조회한 근거가 그 답변에 사용된 경우에만 표시한다.

## 실제 데이터 경로

선택지는 승인된 표의 date 열에서 서버가 발급한다. 선택 ID와 질문 ID는 같은 대화·버전·권한 범위·자료 정의에 묶인다. 클라이언트가 보낸 선택은 Firestore 트랜잭션에서 검증하고, 사용자 선택 원본·처리 중 요청·확인 질문 소모를 함께 저장한다. 실패한 모델 응답 때문에 선택을 되돌리거나 이전 선택을 새 요청에 다시 사용하지 않는다.

조회 직전에 현재 자료 정의를 다시 확인하고 그때의 사본 버전을 고정해 조회한다. 선택 당시의 버전·정의와 실제 조회의 버전·근거 ID는 별도 기록한다. 자료 정의 조회와 선택 저장이 하나의 원자적 트랜잭션이라는 주장은 하지 않는다. 재검증과 불변 버전 조회로 그 사이의 변경을 방어한다.

다른 자료의 조회가 성공하고 대화가 완료된 경우 이전 날짜 기준과 확인 대기를 정리한다. 모델이 맥락에 다른 자료를 적었거나 조회가 실패한 것만으로 사용자 선택을 삭제하지 않는다. 내부 선택 원본과 권한 식별값은 공개 응답에 넣지 않는다.

## 검증과 남은 범위

실제 Firestore·DuckDB·HTTP 브라우저 흐름에서 선택 → 새로고침 → 잘못된 날짜 조회 차단 → 선택 보존 → 올바른 조회 결과를 확인했다. 자유문장으로 버튼 문구를 보내도 조회 0회이며, 오류 후 편집 소스는 유지된다. HTML 대화에서도 같은 선택·조회·재열기가 동작한다. 독립 테스트는 스키마가 모델 호출 도중 바뀌는 경우와 조회 후 권한이 회수되는 경우를 추가해 결과 폐기를 확인한다.

첫 전체 회귀는 1,174/1,174, 타입 검사·빌드가 통과했다. 이후 답변 표시를 실제 사용한 근거에만 한정하는 변경은 실제 저장소 회귀 21/21로 추가 확인했다. 최종 독립 검사 34/34와 전체 브라우저 84/84가 통과했다. 합성 모델을 사용한 경로 검사이며 실제 모델의 날짜 기준 해석 정확도를 측정한 결과는 아니다.

남은 범위는 다음과 같다.

- 모델이 모호함을 놓치는 문제와 명확한 자연어의 날짜 기준을 확인 없이 정확하게 연결하는 문제
- 여러 집계를 요구했을 때 모두 반환했는지 검사하는 요청 계약
- 선택 후 같은 대화에서 날짜 제한을 명시적으로 해제하는 조작. 현재는 날짜 없는 전체 조회를 임의로 보정하지 않고 차단하므로 새 대화가 필요하다.
- timestamp의 시간대 해석

이 한계가 있어 S24 전체 완료나 TOI 전체 인수로 표시하지 않는다. 원본 사업 데이터·권한 부여·주정산·월결산·JVM은 변경하지 않는다.
