## QA에서 발견하여 수정한 결함

- 로그인 계정이 토큰 대기 중 바뀌면 다른 계정으로 저장이 전송될 수 있었다. 토큰 전후와 전송 전에 계정을 확인한다.
- 저장 응답 유실 후 401을 받으면 원래 작업 번호가 사라졌다. 과거 결과가 미확정인 번호는 인증 실패로 삭제하지 않는다.
- 권한 사본의 같은 시각을 `Z`/`.000Z`로 표현하면 충돌 검사를 우회했다. 실제 시각과 정규화된 권한 내용을 비교한다.
- 로그 복사가 동시에 실행되면 커서가 역행하고 오래된 기록이 영구 누락될 수 있었다. 세대 번호 CAS와 원본 갱신 시각을 사용하고, 증분 조회 외에 문서 ID 전체 순환을 수행한다. 전체 순환을 완료한 시각을 별도로 기록한다.
- 브라우저 CSP 차단을 Docker 네트워크 격리로 오인할 수 있었다. 브리지 네트워크에서 실제로 도달하는 수신점을 먼저 확인한 뒤, 같은 이미지의 network none 컨테이너에서 브라우저를 거치지 않는 TCP/DNS를 검사한다.
- Docker 삭제 전에 실행 예약이 해제됐다. 실제 삭제 성공 전까지 예약을 유지하고, 실패하면 제한 재시도와 외부 만료 정리를 수행한다. 재시작 시 잔존 관리 컨테이너가 있으면 새 할당을 시작하지 않는다.
- 저장 응답을 잃은 뒤 권한 범위가 바뀌면 같은 요청이 새 문서로 만들어질 수 있었다. 원래 요청 번호를 사용자·권한 범위·경로·본문 해시에 고정한다. 범위가 다르면 409와 구체적인 안내를 반환하고 이전 원문과 요청 번호를 보존한다. HTML·React·API 모두 실제 저장 후 권한 변경 재시도로 검증했다.

## 권한 변경으로 남은 저장 요청

권한 범위가 변경되어도 원래 요청과 atomic 영수증의 사용자·경로·메서드·본문 해시가 일치하고, 현재 권한으로 정확한 불변 버전을 다시 조회할 수 있으면 복구 화면에 표시한다. 사용자가 불러오기를 확정한 경우에만 브라우저 요청 번호를 정리한다. 복구는 읽기만 수행하며 문서·버전을 추가하지 않는다. React 연결 API 일부의 권한 회수, 최신 API 중지, 조회 중 계정 비활성화도 검사한다.

`scope_changed`가 계속 남는 경우는 현재 권한으로 읽을 수 없거나 원래 영수증을 충분히 확인할 수 없는 경우다. 이를 사용자가 강제 해제하는 UI는 제공하지 않는다. 권한을 과거 상태로 되돌리거나 브라우저 기록을 일괄 삭제하는 방식으로 해결하지 않는다.

운영자는 독립 Workbench 저장소에서 해당 사용자와 원래 요청 번호의 `workbench_operation_scopes`, 원래 범위의 `workbench_mutation_results`, 대응 문서 ID·버전을 읽기 대조한다. 원문은 현재 조회 권한이 있는 사람만 확인한다. 완료 영수증이 있고 해당 문서를 현재 권한으로 열 수 있으면 기존 문서를 편집 대상으로 선택하고, 지원 담당자가 그 요청 하나의 브라우저 복구 상태만 정리한다. 미실행 판정에는 진행 중 요청·영수증·문서 버전까지 확인해야 하며 `not_found` 응답 하나로 판단하지 않는다. 처리 여부가 불명확하거나 문서 접근 권한이 없으면 보존한다. 이 절차는 운영 지원 절차이며 사용자 자체 복구 기능으로 보고하지 않는다.

## 토스 TOI와의 차이

정책/API와 생성 화면을 분리하고, 고정 패키지 조합을 미리 준비하며, 성공한 실행만 화면에 반영한다. 그러나 브라우저 esbuild-wasm/HMR을 사용하지 않는다. 서버의 제한된 컴파일 프로세스와 세션별 원격 Chromium을 사용한다.

운영 React는 사용자 브라우저에서 생성 스크립트를 실행하지 않는다. PNG 화면을 받고 클릭·입력·스크롤을 전달한다. 따라서 일반 DOM과 달리 텍스트 선택과 스크린리더 접근에 제한이 있으며 UI에도 표시한다. 로컬 iframe은 에뮬레이터 테스트 전용이다. 임의 npm 패키지 설치도 지원하지 않는다.

첫 화면 시간은 실제 컨테이너 생성부터 첫 PNG까지 측정한다. 토스의 1.3초 수치를 이 구현의 성능으로 사용하지 않는다. OOM 한도 설정 확인과 실제 커널 OOM 관측도 구분한다.

## 운영 연결 전에 필요한 구성

현재 Cloud 인증은 복구되어 읽기 전용 목록 조회가 가능하다. 기존 운영 모델 시크릿의 존재만 확인했고 값은 읽거나 재사용하지 않았다. 독립 GCP 프로젝트·호스트·새 IAM·시크릿은 생성하지 않았다.

권장 구성은 기존 서비스와 다른 GCP 프로젝트의 전용 Docker 호스트 1대, 독립 Firestore, 전용 모델 할당량/인증, 전용 GitHub App이다. 초기 실행 상한은 전체 4개, 사용자 정상 화면 1개와 교체 후보 1개다. 호스트에 외부 reaper timer를 설치한다. 권한 사본은 짧은 주기로 공급하며 공급이 중단되면 기존 만료 정책에 따라 접근을 차단한다.

운영 연결에는 다음을 확정해야 한다.

1. 새 유료 실행 호스트와 독립 프로젝트의 대상·예산. 호스트 사양은 broker의 자원 한도와 최대 4개 renderer, OS 여유분을 합산한 뒤 부하 검증으로 확정하며 실제 비용은 지역·가동시간·디스크에 따라 결정된다.
2. 로그인 프로젝트와 원본 구성원 ID의 대응, 전용 계정의 원본 권한/허용 로그/승인 시트 읽기 범위. 애플리케이션 서버는 사본만 읽고 쓰며 원본 쓰기 권한을 받지 않는다.
3. 전용 모델 시크릿과 비공개 Git 저장소/전용 GitHub App. 공개 MYSCube 저장소는 합성 테스트에만 사용한다.
4. 지정 외부 API의 주소·인증 방식·서버 시크릿 이름과 읽기 응답 스키마. 운영자가 승인한 엔드포인트만 등록 목록에 노출한다.

`workbench-ci.yml`은 기존 업무 CI와 별도로 검증한다. `workbench-deploy.yml`은 승인된 독립 Cloud Run의 무트래픽 후보까지만 준비하는 산출물이다. Docker broker는 Cloud Run 안에서 실행할 수 없으며 코드도 이를 거부한다. 따라서 이 파일만으로 원격 React의 운영 배포가 끝났다고 표현하지 않는다. 전용 호스트의 운영 설치·로그인·실제 모델·승인된 데이터 연결 및 장애 시험이 별도 필요하다.

## 증거

- 최종 통합 검증: Workbench Vitest **435/435, 54개 파일**, 독립 TypeScript·Vite 빌드 통과. 생성 모델은 fixture를 사용하며 Firestore 에뮬레이터·HTTP·DuckDB·브라우저의 실제 저장과 읽기를 검증한다.
- 최종 브라우저 검증: Playwright **26/26**, 40.6초. 저장·복원·지속 대화·API 등록·권한 회수·후보 화면 교체·응답 유실 후 복구를 실제 브라우저에서 확인했다. 원격 화면 UI의 HTTP fixture 검증과 실제 Docker 격리 검증은 별도 증거다. Studio 테스트는 이전 iframe 존재를 새 요청의 완료로 오인하는 경쟁 조건을 수정한 뒤 전체를 다시 통과했다.
- 실제 Git 저장 전달 증거: [합성 React 원문 PR817](https://github.com/merryAI-dev/MYSCube/pull/817).
- 실제 Linux 격리 증거 수집용 [Draft PR818](https://github.com/merryAI-dev/MYSCube/pull/818). 플랫폼 전체 배포 PR이 아니며 머지하지 않는다. 최신 커밋과 일치하는 강화 probe 결과만 판정에 사용한다.
- 실제 Linux 검증 [run 35863959611](https://github.com/merryAI-dev/MYSCube/actions/runs/35863959611), 커밋 `a7aabfa5`, PASS. [전체 증거 JSON](evidence/2026-09-23-runtime-isolation.json)에 원시 TCP/DNS 차단과 도달 가능한 대조군, 공격 실행 중 별도 세션 응답, 강제 종료·만료 정리·재시작 차단을 기록했다. 첫 화면 1,081ms/다음 세션 1,025ms는 각 1회이며 운영 SLO가 아니다. 무한 반복·메모리 압박·API 폭주 중 별도 세션 응답 최대치는 각각 21/28/28ms였다. 메모리 제한 설정은 확인했으나 커널 OOM은 관측하지 않았다. 만료 정리 검증은 테스트 시계를 이동한 실제 Docker 삭제이며 운영 타이머 설치 증거가 아니다.
- 모델 생성은 fixture로 데이터 경로를 검증했다. 실제 모델의 답변 정확도·생성 품질·운영 로그인·실제 Sheets/외부 API는 검증 완료로 포함하지 않는다.

## 후속 패키지·운영 준비 보완

- Cloud Run 후보는 이미 존재하는 승인된 서비스만 대상으로 한다. 보호된 임시파일로 읽은 설정에서 필수 프로젝트·인증 값과 독립성, 서버/프론트 인증 프로젝트 일치를 빌드 전후 검사한다. 설정값과 비밀값은 로그에 출력하지 않는다. 실제 서비스나 권한은 만들지 않았다.
- 독립 앱 이미지의 Linux 빌드·정적 자산·401·React/Tailwind·native DuckDB·정상 종료 smoke를 CI에 추가했다. 로컬 macOS COPY 재현을 Linux 이미지 검증으로 취급하지 않는다.
- [전용 호스트 설치 계약](../../../server/workbench/host-runtime/README.md)은 별도 host/systemd와 loopback→TLS proxy 구성, env 소유권과 Docker 권한, reaper/rollback/실운영 수용 기준을 명시한다. 템플릿을 실제로 설치하지 않았다.
- 종료 시 HTTP 연결과 Docker 삭제 확인 후 DB를 종료하며, 총 10초 내 끝나지 않으면 실패 종료한다. 종료 중 인증 대기가 끝난 요청도 새 컨테이너를 만들지 않는다. 삭제 실패를 숨기거나 실행 예약을 먼저 반환하지 않는다.

## 전체 PR 분리 중 추가 회귀 확인

- 기존 요청 로그의 배포 버전·환경·요청 번호와 client-errors 호환 필드는 유지한다. 별도 분석 저장 호출을 응답 경로에서 제거해도 기존 로그 근거를 버리지 않는다. 기존 BFF HTTP·Firestore 회귀 62/62를 확인했다.
- 임시저장의 수동/자동 saveMode 인터페이스·CAS·lease·payload를 유지하고 별도 관측 호출과 전용 헤더만 제거했다. 임시저장·편집기 회귀 69/69를 확인했다.
- 기존 정산 canary의 순서·조건·명령·환경은 유지하며 Workbench 전용 배포 설정/검증만 제거한다. 독립 QA와 배포 회귀 10/10을 확인했다.
