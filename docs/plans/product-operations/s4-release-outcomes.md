# S4 — 배포 효과와 포트폴리오 성과
## 목표·진입 조건
S2 지표 정의가 고정되고 S3 사건·배포 연결이 가능해야 한다. 측정 기간의 성공 분모와 수집 품질이 확보돼야 효과를 판단한다.

## 작업
1. GitHub 배포 SHA·시각·대상 서비스·공식 주소 반영 결과를 업무 지표에 연결한다.
2. 배포 전후 동일 길이 구간 및 같은 업무/역할/프로젝트 코호트를 비교한다. 근무일·마감일·이용량·계측 버전 변화를 함께 설명한다.
3. 오류율, 입력 차단율, 제출 완료율, 소요 시간, 재발, 문의량을 제공한다. 문의가 미계측이면 0으로 쓰지 않는다.
4. 배포됐다는 사실과 해결됐다는 판정을 분리한다. 관련 업무 성공과 충분한 관찰이 없으면 관찰 중으로 유지한다.
5. 보고서를 기간·분자·분모·제외 조건·지표 버전·추출 시각이 포함된 스냅샷으로 저장한다.

## 실제 경로·산출물
읽기 전용 배포 이력 + 사건 + 지표 집계 → 비교 API → 운영 보고서/비식별 성과 내보내기.
예: 4%→1%는 3%p 감소, 상대 75% 감소다. 예시를 실제 성과 숫자처럼 보여주지 않는다.

## QA·완료 조건
차트와 원본 집계를 재계산해 값이 같다. 분모 0·극소 표본·부분 기간·수집 중단·시간대 경계·배포 롤백·동시 배포를 검증한다.
전후 비교는 관측 변화로 표시하고 인과 효과로 주장하지 않는다. 측정 시작 전의 성공 분모를 추정해 메우지 않는다. 원시 횟수 감소와 실패율 감소가 명확히 구분되면 통과한다.

## 중단·복구
지표 정의 오류가 발견되면 해당 보고서에 정정 표시하고 새 버전을 발행한다. 공개용 자료에는 개인·사업 식별자를 제외하고 별도 검토한다.
