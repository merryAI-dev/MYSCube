# S24 — 미리보기 지연의 다음 검증 범위

2026-09-28 독립 QA 소스 검토. 설계 제안이며 구현·운영 적용하지 않았다.

실호스트 측정의 renderer init 약 1.55초는 Chromium 시작, 컨텍스트 생성, CDP 연결, 패키지와 사용자 화면 실행을 포함한다. 브라우저 시작만의 시간이 아니므로 사전 준비로 전부 제거할 수 있다고 해석하지 않는다. 완료 컴파일 캐시는 동일 소스 재실행에 도움을 주지만 변경된 소스와 새 렌더러 생성 지연은 남는다.

가능한 실험은 사용자 소스나 API 연결 없이 고정 런타임의 Chromium을 미리 시작하는 것이다. 사용하지 않은 실행 공간 최대 1개를 최초 사용자에게 한 번만 귀속하고, 사용하거나 실패한 공간은 다시 다른 사용자에게 제공하지 않는다. 새 클라우드 리소스를 추가하는 제안은 아니다.

독립 검토에서 다음 경계가 필요했다.

- 준비·대기·사용·종료 중인 공간을 모두 기존 전체 4개 한도에 포함한다. 사용자 요청보다 대기 공간 보충이 우선하지 않도록 한다.
- 기존 인증·소스 검사·사용자별 한도 이후 원자적으로 한 사용자에게 귀속한다. 응답 직전 권한을 다시 확인한다.
- 귀속 전에는 사용자 소스·프레임·API 호출을 허용하지 않는다. 이미지·패키지 버전과 준비 완료 신호가 일치하지 않으면 폐기한다.
- 종료와 삭제 확인 전까지 점유량에 포함한다. 실패한 공간을 대기 목록으로 돌려놓지 않는다.
- 현재 worker와 reaper의 수명은 컨테이너 생성 시각 기준이다. 사용자 귀속 시각으로 수명을 임의 연장하면 서로 충돌한다. 짧은 대기 수명과 충분한 잔여 사용 시간을 검증하고 오래된 대기 공간은 폐기해야 한다.

필수 반증은 동시 귀속 경쟁, 다른 사용자 상태 잔존, 귀속 도중 권한 회수, 잘못된 버전, 준비 실패, 삭제 지연, 종료·만료·재시작이다. 실제 호스트에서는 준비 단계별 시간, 첫 화면 20회, 유휴 공간을 포함한 메모리와 2사용자 동시 실행을 다시 측정해야 한다. G4 자원 계측 오류가 해결되지 않은 상태에서 이 최적화를 성능 통과나 안전한 운영 적용으로 인정하지 않는다.
