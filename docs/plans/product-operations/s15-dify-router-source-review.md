## Comparison with current MYSCube workbench

MYSCube is deliberately narrower than Dify:

1. `conversation-routes.mjs` authenticates, checks admin role, starts an idempotent turn, enforces a deadline, then persists complete or failed state. Dify’s controller/service split is analogous, but Dify has app-wide message and workflow concerns that MYSCube does not need.
2. `conversation-agent.mjs` performs one bounded typed loop with an allowlisted catalog and a maximum number of queries/investigations. This serves the router/classifier role without a per-question endpoint or graph DSL.
3. `conversations.mjs` stores versioned turns and request fingerprints. It is stricter than a transient browser chat: duplicate request IDs replay and different source hashes conflict.
4. `html-bindings.mjs` converts verified evidence to escaped server-side DOM text/table nodes. Dify’s tool runtime is a useful separation precedent, but it does not substitute for MYSCube’s evidence provenance and static HTML policy.

## Decision and limits

Adopt these architectural patterns: one typed router, explicit clarification state, actor-scoped persistent turns, declared read tools, bounded history, and server-side error/stop states.

Do **not** adopt Dify’s application DSL, graph runtime, plugin/tool marketplace, SQLAlchemy persistence model, or broad tool abstraction. They would increase the trusted computing base and blur MYSCube’s business SSoT. Current work only has fixture/model-adapter tests; no live model provider behavior is proven by this review.

### Concrete route/classifier/executor chain

1. Dify validates/imports workflow DSL node data, including a question-classifier node, in [`services/app_dsl_service.py`](https://github.com/langgenius/dify/blob/3a017e8cccb316f23f601af65d2e8ce92e68f788/api/services/app_dsl_service.py). Its node factory delegates the typed node to Graphon’s node factory.
2. Graphon’s [`SlimDslNodeFactory._create_question_classifier_node`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/dsl/node_factory.py#L676-L699) creates `QuestionClassifierNode` with a concrete model runtime, prompt renderer, file saver and shared `GraphRuntimeState`. [`NODE_BUILDERS`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/dsl/node_factory.py#L830-L858) maps `QUESTION_CLASSIFIER` to that factory method.
3. The classifier is explicitly a branching node. [`QuestionClassifierNode._invoke_classifier`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/nodes/question_classifier/question_classifier_node.py#L343-L367) invokes the model. [`_resolve_category`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/nodes/question_classifier/question_classifier_node.py#L370-L406) accepts only a known `category_id` from parsed output and sets `edge_source_handle` to it in [`_build_success_result`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/nodes/question_classifier/question_classifier_node.py#L430-L469).
4. **Classifier fallback is deterministic, not confidence based.** If parsed output omits `category_name`/`category_id`, or contains an unknown ID, `_resolve_category` returns the *first configured class*. Model invocation/JSON `ValueError` becomes a failed node result in [`_run`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/nodes/question_classifier/question_classifier_node.py#L229-L261). This is appropriate only when a workflow author deliberately makes the first class a safe default. It is not a pattern MYSCube should copy for business routing.
5. Graphon’s [`GraphEngine`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/graph_engine/graph_engine.py#L52-L178) owns the ready queue, state manager, edge processor, command processor, worker pool and dispatcher. Its [`run/_run_graph`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/graph_engine/graph_engine.py#L212-L263) emits success/failure/paused/aborted graph events; resume restores container/ready-task state in [`_start_execution`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/graph_engine/graph_engine.py#L303-L350). Abort/pause/update-variable commands are handled in [`command_handlers.py`](https://github.com/langgenius/graphon/blob/11e2dee8cbd6dc2e6bf1c2059d9bbf4d0437ebe5/src/graphon/graph_engine/command_processing/command_handlers.py#L17-L65).

### Updated MYSCube conclusion

MYSCube should **not** emulate Graphon’s classifier fallback-to-first-class behavior. A missing/unknown route must become `clarification_required` or a typed failure; no route may silently select a dataset, project status, approval action or screen layout. Our compact `workbench_step` schema and persisted clarification turn are safer for this domain because they make a non-decision observable and resumable without granting a graph executor or write-capable tool runtime.

The reusable part is only the separation: typed route result → declared edge/next step → explicit persisted stop/error/resume state. The non-reusable part is Graphon’s general workflow execution substrate, parallel worker machinery, plugin runtime and default branch convention.
