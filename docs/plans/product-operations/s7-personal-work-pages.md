# S7 개인 업무 페이지

## 목적과 범위

2026-09-22 추가 요청. 각 구성원이 현금흐름 조회 또는 공개 서비스 안내를 개인 업무 화면으로 구성하고, 저장 당시 구성을 다시 열 수 있게 한다. 자연어 제안도 같은 구성 스키마를 통과한다. 운영 사업 자료·정산 처리·프로젝트 임시저장과 별개의 개인 설정이다.

## 토스와 공개 구현에서 가져온 원칙

[토스 TOI 원문](https://toss.tech/article/52885)은 정책과 화면 실행을 분리하고 사용자별 실행 상태를 격리한다. MYSCube는 우선 등록된 React 컴포넌트와 엄격한 JSON 구성으로 이를 구현한다. 임의 React 코드·패키지를 실행하는 esbuild/iframe 런타임까지 도입하는 범위는 아니다. [ToolJet의 조회 권한](https://docs.tooljet.ai/docs/app-builder/connecting-with-data-sources/creating-managing-queries/)처럼 페이지 접근과 실제 조회 권한을 따로 검사한다. [ToolJet의 공개 보안 사례](https://github.com/ToolJet/ToolJet/security/advisories/GHSA-pqfh-276q-w3cp)는 화면 정의/데이터 소스 단위의 권한 검사를 생략하면 조직 경계를 넘을 수 있음을 보여준다.

## 실제 데이터 경로

`/work-pages`, `/portal/work-pages` → 인증된 BFF → `orgs/{tenant}/personal_work_pages/{sha256(actorId)}/pages/{id}`. 버전은 해당 페이지의 `versions/{version}`에 create-only로 남긴다. 본문에는 제목·설명·허용 소스·표/카드·연월·검색어만 저장한다. 사업 결과, 인증 토큰, 임의 URL/스크립트는 구성 필드로 받지 않는다.

- 작성: expectedVersion=0 → 버전1.
- 수정: 저장된 expectedVersion과 일치할 때만 새 버전. 충돌은409, 입력 유지.
- 복원: 이전 구성의 현재 스키마 검증 → 새 버전 생성. 옛 버전 덮어쓰기 없음.
- 삭제: 개인 페이지 비활성 표시와 새 이력. 사업 자료는 변경하지 않음.
- 조회: 개인 페이지 소유와 관계없이 원래 로그인 사용자의 현금흐름 API 권한을 다시 검사.
- 모델 제안: 서버 strict 스키마/연월 검증 → 사용자 명시적 적용 → 직접 저장. 자동 저장 없음.

## 완료 게이트

1. 소유자·다른 사용자·다른 조직의 CRUD/복원 대조 및 Firestore 직접 접근 거부.
2. 실제 HTTP idempotency 재전송, 저장/재조회, CAS409, 버전3 복원 확인.
3. 브라우저 새로고침/재열기/복원, 모바일 폭, 조회 실패 상태 확인.
4. 모델 키 없이 직접 구성이 동작하고 자연어 제안은 미설정 상태를 안내.

## 제한과 복구

목록/이력은100개 표시 상한을 명시한다. 임의 코드 실행·공유 페이지·공동 편집·자동 업무 실행은 제공하지 않는다. 기존 API가 실패하면0원/빈 데이터로 바꾸지 않는다. 문제가 생기면 새 화면의 진입을 중단하되 저장 구성을 삭제하지 않는다. 자연어 모델 활성화 조건은 S8 문서 참조.
