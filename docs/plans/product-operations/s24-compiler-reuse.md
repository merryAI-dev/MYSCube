# S24 — 완료된 React 컴파일 결과 재사용

2026-09-28 구현·독립 QA 완료. 운영 미배포. 생성 후 미리보기와 저장에서 같은 소스와 API 계약을 다시 컴파일하던 경로를 개선했다.

서버가 확인한 테넌트·사용자·조회 권한 범위별로 성공한 결과만 재사용한다. 소스, 시작 파일, API 전체 정의·입력·응답 형식·버전, 패키지와 컴파일러 식별값이 같아야 한다. 입력의 동일한 불변 직렬화 값을 키와 실제 컴파일 입력에 사용한다. 인증·API 사용 가능 여부·요청 한도 검사는 매번 유지한다. 권한 범위나 현재 컴파일러 식별값을 확인할 수 없으면 재사용하지 않는다.

유효기간은 5분이며 사용자 범위별 4개, 전체 32개·직렬화 크기 8MiB로 제한한다. 이는 프로세스 전체 메모리 한도가 아니다. 실패·취소·실행 중 작업은 공유하지 않으며 반환값은 복제한다. 소스가 바뀌면 다시 컴파일하므로 첫 화면 또는 편집 후 미리보기 속도 목표를 달성했다는 의미는 아니다.

독립 QA 77/77 통과. 생성→HTTP 미리보기→Firestore 저장 및 저장된 대화→미리보기→저장 흐름에서 실제 TypeScript/esbuild 자식 실행 1회를 확인했다. 모델과 원격 브로커는 이 검사에서 fixture다. 재사용 상태의 권한 철회 403, API 중지 409, 요청 한도 초과 429도 확인했다.

전체 Workbench 회귀는 실제 React 브라우저 검사를 포함해 108개 파일·1,143개 테스트가 통과했다. 실제 저장소 연동을 포함한 Playwright 82/82, 타입 검사와 독립 프런트엔드 빌드도 통과했다. 환경 변수 없이 실행한 최초 브라우저 실행의 30개 skip은 인수 증거로 사용하지 않고, Firestore 연결을 활성화한 전체 실행 결과로 확인했다. 빌드의 500KB 청크 경고는 남아 있다. 실제 운영 호스트에서의 개선 수치와 사용자 로그인 경로는 이 검사에 포함하지 않았다.

별도 CI에서는 전문 프로필 점수 `920` 유출 검사에 무작위 UUID 일부가 우연히 일치했다. 응답·감사·멱등 기록의 문자열/숫자 값 자체를 재귀 검사하도록 테스트만 수정했고, 독립 43/43 통과했다. 개인정보 검사나 제품 API 정책은 제거하지 않았다. 이전 실패 기록은 보존한다.
