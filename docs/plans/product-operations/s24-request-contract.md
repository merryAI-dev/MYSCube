# S24 — 질문의 기준과 실제 조회 결과를 연결하는 계약

상태: 독립 소스 검토 후 설계. 이 문서의 날짜 확인·집계 충족 기능은 아직 구현하지 않았다. S23 실제 자료 평가에서 같은 질문이라도 모호한 날짜 기준을 임의로 고르거나 요청한 집계를 빠뜨리는 사례가 관측됐다. 다시 실행했을 때 성공한 사실은 이 결함의 해결 증거가 아니다.

## 원인과 변경 경계

현재 대화 맥락의 기간은 시작일·종료일만 저장하고 어느 날짜 열 기준인지는 저장하지 않는다. 표 조회 검증은 그 기간을 만족하는 날짜 열이 있는지 검사한다. 실제 계산은 정확해도 사용자가 뜻한 기간인지 보장하지 못한다. 마지막 응답은 근거의 출처를 검증하지만 필요한 집계를 모두 반환했는지는 확인하지 않는다.

질문별 새 API나 원본 DB 파이프라인을 추가하지 않는다. 등록된 읽기 전용 표의 스키마와 기존 조회 컴파일러를 사용한다. 원본 업무 데이터, 주정산·월결산, JVM 변경은 범위 밖이다. 모델이 제안한 조건과 사용자가 확인한 조건을 구별한다.

## 날짜 기준

서버가 저장하는 요청 계약에 자료 ID, 스키마 식별값, 날짜 열, 선택한 조건, 확인 질문·선택 ID와 권한 범위를 포함한다. 확정 근거는 승인된 업무 정의의 시간 기준 또는 실제 사용자 선택이다. 모델이 반환한 `explicit_request` 문자열이나 자연어 인용만으로 확인 완료라고 표시하지 않는다.

서로 다른 날짜 기준에 따라 결과가 달라지고 기준을 확정할 수 없으면 조회를 실행하기 전에 같은 대화에서 짧게 묻는다. 예: “계약 시작일과 계약 종료일 중 어느 날짜를 기준으로 볼까요?” 선택지는 현재 자료에 실제 존재하는 필드의 업무 이름으로 만든다. 새 업무 관계나 기간 겹침의 의미를 임의로 추가하지 않는다.

선택 응답은 현재 저장된 확인 질문의 ID와 선택 ID로 검증한다. 이미 끝난 질문, 다른 자료·권한·스키마의 선택은 거부한다. 자유 문장으로 요청을 바꿀 수 있지만 모델이 그 문장을 임의로 선택 완료 처리해서는 안 된다. 명확한 요청까지 모두 반복 확인하는 구현은 인수하지 않는다.

확정된 날짜 기준은 같은 자료·스키마·권한에서 후속 요청에 재사용한다. 사용자가 기간만 바꾸면 날짜 기준은 유지하고, 다른 자료로 전환하면 이전 기준을 적용하지 않는다. 화면에는 “계약 종료일 기준 · 2026년 9월”처럼 조회 기준을 서버 계약에서 표시한다.

## 필요한 집계와 반환 결과

요청 계약은 필요한 결과를 행 목록, 문서 수, 중복 제외 값 수 등으로 구분하고 대상 열·그룹 여부·필터·기간을 보존한다. 실제 근거의 실행 계획과 불변 자료 버전이 이 계약을 만족하는지 확인한다. 조직별 문서 수는 중복 제외 조직 수 하나를 요구한 요청을 충족하지 않는다.

결과 두 개가 필요한데 하나만 조회했으면 남은 조회를 기존 한도 안에서 수행하거나 미완료 항목을 명시한다. 최종 응답이 요구 항목을 삭제하여 완료로 바꾸지 못하게 한다. 답변·HTML·React 화면 모두 같은 검사를 적용한다. 미확인 값, null, 빈 문자열, 0은 기존 정책대로 구별한다.

요청 계약 자체를 모델이 빠뜨릴 수 있다는 한계가 남는다. 같은 모델의 계약과 계획이 일치한다는 사실만으로 원래 질문의 의미까지 검증됐다고 주장하지 않는다. 독립 해석 검사는 불일치를 발견해 확인 질문으로 보내는 보조 수단이며 자동 승인 근거가 아니다.

## 단계별 인수 증거

1. 모호한 날짜 요청에 모델이 모호함이 없다고 반환해도 확정 근거가 없으면 조회 0회로 확인 질문을 표시한다. 기존 편집·근거·화면을 보존한다.
2. 실제 사용자가 선택한 날짜와 다른 열, 오래된 질문 ID, 다른 스키마·권한의 선택으로 조회할 수 없다. 기간만 바꾼 후속 요청은 확정 기준을 유지한다.
3. 실제 분석 엔진에 중복 값·null·빈 문자열을 넣어 문서 수, 중복 제외 값 수, 누락 건수를 구별한다. 그룹별 결과를 스칼라 요구의 완료로 계산하지 않는다.
4. 두 결과 중 하나만 돌아온 경우, 오류·재질문·권한 철회·응답 재전송에서도 미완료 항목과 이전 정상 화면이 보존된다.
5. 비개발자가 선택한 조건과 화면의 근거·자료 시각을 브라우저에서 직접 대조한다. 별도 구조화된 API 테스트만으로 UI 인수를 대신하지 않는다.
6. 이미 검토한 S23 질문은 회귀 세트로 유지한다. 개선 후 일반화 정확도는 독립 QA가 새로 봉인한 질문 전체로 평가하고 이전 실행과 좋은 결과만 합치지 않는다.

소스 검토 대상: `conversation-agent.mjs`, `table-query.mjs`, `react-screen-bindings.mjs`, `conversations.mjs`. 날짜·집계 계약을 도입하기 전까지 제한된 조건 재작성 기능을 이 문제 전체의 해결책으로 표시하지 않는다.
