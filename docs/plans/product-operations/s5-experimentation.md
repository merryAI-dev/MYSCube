# S5 — 장기 A/B 실험과 그로스 측정
## 목표·진입 조건
S4까지 지표가 안정화되고, 예상 트래픽으로 의미 있는 효과를 판단할 수 있는지 먼저 계산한다. 표본 부족이면 실험을 강행하지 않는다.

## 작업
1. 가설, 대상, 주 지표 하나, 안전 지표, 최소 감지 효과, 표본·관찰 기간, 중단 조건을 등록한다.
2. 첫 대상은 안내 문구·입력 순서 같은 UX로 한정한다. 데이터 보존·권한·필수 검증 완화는 실험하지 않는다.
3. 사용자 또는 프로젝트 단위로 고정 배정한다. 협업이 변형을 서로 전파하면 프로젝트/조직 단위 배정을 검토하고 분석 단위를 맞춘다.
4. 실제 노출 이벤트를 기록한다. 배정만 되고 보지 않은 사용자를 노출자로 세지 않는다.
5. A/A 검증, 표본 비율 불일치(SRM), 누락/중복 노출 검증 후 효과를 분석한다.
6. GrowthBook을 우선 검토하되 PostHog와 기존 데이터 연결·라이선스·유지 비용을 비교한다. 통계 엔진을 직접 새로 만들지 않는다.

## 실제 경로·산출물
실험 등록 → 고정 배정/노출 → 동일 업무 이벤트 → 집계 → 통계 엔진 → 결과와 신뢰도.
구성원에게는 배정에 따라 화면이 일관되게 보이고 운영자는 실제 노출·표본·보호 지표를 확인한다.

## QA·완료 조건
새로고침·재로그인·다중 기기에서 정의한 배정이 유지된다. 종료된 실험·캐시된 플래그·SDK 장애에서 안전한 기본 화면으로 동작한다.
실험 시작 전 분석 방법을 고정한다. 매일 결과를 보고 유리할 때만 종료하지 않는다. 순차 검정을 쓰면 해당 방법·조건을 명시한다.
초안 유실·승인 불일치가 발생하면 즉시 중단할 수 있어야 한다. SRM 또는 표본 부족 시 승자 대신 판단 불가로 표시한다.

## 중단·복구
플래그를 기본 변형으로 되돌려도 임시저장과 승인 데이터는 호환돼야 한다. 실험 결과·배정 버전을 지우지 않는다. 새 외부 서비스·이벤트 전송·비용은 도입 전 범위를 확정한다.
