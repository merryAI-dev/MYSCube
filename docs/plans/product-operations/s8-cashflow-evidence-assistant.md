# S8 현금흐름 근거 기반 에이전트

## 목적

전사 현금흐름에 대해 실제 반영 금액, 조회 실패, 최근 화면 오류와 코드 동작을 함께 확인한다. 사실·원인 후보·추가 확인을 구분하며 코드 설명만으로 실제 장애 원인을 확정하지 않는다. 주정산/월결산 명령·동기화·시트 반영 로직은 수정하지 않는다.

## 데이터 경로와 근거

`/cashflow-assistant`, `/portal/cashflow-assistant` → 인증 BFF `cashflow-evidence` → 기존 `readCashflowSnapshot` → `accountingEvidence`.

- 인증 계정의 현재 활성 상태와 역할 확인, 기존 사업 범위로 조회. 담당자에게 다른 사업명·목록 커서를 노출하지 않는다.
- 페이지당10개, 최대3개 동시조회, 사업당5초 상한. 특정 사업 실패는 다른 사업 결과를 버리지 않는다.
- 반영 버전, 조회 시각, 누락 주차,0원/미확인, 페이지별 포함/제외를 구분한다. 모든 페이지를 같은 시점의 전사 합계로 합치지 않는다.
- 주별/연간 고정 좌표는 기존 계약을 그대로 사용한다. 연간 범위를 월별0원으로 만들지 않는다.
- 관리자 진단은 현재 조직의 최근 화면 오류100건 중 현금흐름 관련 메타데이터만 제공한다. 로그 ID·시각·수집 서버 배포를 표시한다. 원문·스택·개인정보는 제외한다. Cloud Logging 전체 또는 해당 조회와 상관관계가 확인된 원인 로그라고 주장하지 않는다.
- 검토된 `SUPPORT_KNOWLEDGE`의 코드 경로·설명 버전·배포 SHA를 제공한다. SHA 미수집은 확인 불가로 표시한다.

## 모델 경계

기존 Gemini adapter와 도구 실행/grounded-answer 검토를 재사용한다. 모델에는 허용된 `cashflow_evidence`, 관리자 전용 `cashflow_diagnostics`만 노출한다. 테넌트·사용자·권한은 서버 closure에 묶이며 모델 인자로 받지 않는다. 각 도구와 모델 호출 전, 결과 반환 전에 계정 변경을 재확인한다. 미확인·일부 결과·질문 보완 필요를 완료와 구분한다.

생성된 답변과 사용한 근거 원문을 함께 확인한다. 실행 메타데이터는 개인 설정 하위 `agent_runs` 및 이벤트에 저장한다. 원문 질문/모델 답변을 실행 로그에 저장하지 않으며 단계·도구·근거 해시/버전·모델 검토 판정·토큰 수를 기록한다. 해시는 사실의 정확성을 증명하는 도구가 아니다.

## 기본 비활성 및 활성화 전 확인

`PRODUCT_WORKBENCH_AI_ENABLED=true`와 기존 서버의 `SETTLEMENT_AGENT_GEMINI_API_KEY`가 모두 있어야 모델을 호출한다. 이번 작업에서 키·환경변수·활성화 설정을 변경하지 않는다. 비활성 상태에서도 수동 페이지 구성·실제 자료 조회·진단은 사용 가능하다.

활성화하면 Google Gemini에 사용자 질문, 권한 내 사업명/CIC·금액·반영 버전·누락 정보·코드 설명, 관리자 질문이면 필터링된 오류 메타데이터가 전달될 수 있다. 서버 비밀값·사용자 연락처·로그 원문/스택은 전송하지 않는다. 공급자의 보관 조건과 업무 데이터 전달 범위·비용을 운영 담당자가 확인한 뒤 활성화해야 한다. 기존 키 보유만으로 이 범위를 승인한 것으로 간주하지 않는다.

상한: 사용자 하루30회, 조직 하루200회, 사용자 동시1회, 실행55초, 모델4단계, 도구6회, 호출 입력16,000토큰/출력2,048토큰. 같은 HTTP idempotency 키는 과금 가능한 실행을 반복하지 않는다. 실패 요청도 사용량에 포함한다. 이 값은 비용 산정 결과가 아니며 활성화 시 실제 단가·수요와 함께 검토한다.

## QA와 남은 검증

에뮬레이터에서0원·빈 월·시간 초과를 함께 대조하고 실제 업무 문서가 변하지 않는지 확인한다. 브라우저에서는 자료 조회 실패가0원이 되지 않는지 확인한다. 모델 경계 테스트는 스크립트/임의 소스/잘못된 기간 거부와 근거 없는 답변 차단을 확인한다. 실제 모델 호출·응답 품질·활성화 후 지연/비용은 API 키/승인 범위의 별도 게이트다.

참고: [OpenTelemetry 예외 기록](https://opentelemetry.io/docs/specs/otel/trace/exceptions/), [GenAI span 규약](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md). 외부 라이브러리를 새로 도입하지 않고 관측 실패와 업무 실패, 모델 실행과 실제 업무 완료를 구분하는 설계에 반영했다.
