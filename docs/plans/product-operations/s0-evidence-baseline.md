# S0 — 최대 보관 기간 조사와 기준선
## 목표·진입 조건
접근 가능한 자료의 가장 오래된 시점부터 읽는다. 7/28일 같은 UI 기간을 조사 상한으로 쓰지 않는다. 운영 읽기 권한과 소스 소유자를 확인한다.

## 작업
1. Firestore 오류, BFF 런타임, JVM 로그, Sentry, 배포 이력, 감사 기록, 기존 export의 보관 범위를 목록화한다.
2. 소스별 최초/최종 시각, 실제 보관 설정, 접근 실패, 페이지 수, 읽기 종료 지점, 환경 식별 가능 여부를 기록한다.
3. 운영·프리뷰·점검 이벤트를 구분한다. 식별 근거가 없는 자료는 미분류로 남긴다.
4. 오류 코드·화면·배포 버전·요청 ID로 묶고 재시도와 중복을 분리한다. 타임아웃을 서버 장애로 자동 확정하지 않는다.
5. 성공 분모가 남아 있는 구간을 확인한다. 복원할 수 없는 기간은 오류 건수만 표시한다.

## 실제 경로·산출물
client_error_events 및 서비스 로그 → 읽기 전용 조사기 → 비식별 집계 → coverage.json, 원인 후보 목록, 최초 기준 보고서.
현재 확인: 19페이지 9,141건, 저장일 UTC 3/20~9/22. 동시 쓰기 중의 페이지 조회는 원자적 스냅샷이 아니므로 추출 기준 시각과 재조정 절차를 명시한다. 최종 보고서의 날짜 집계는 KST로 변환한다.

## QA·완료 조건
빈 날짜가 오류 0인지 수집 불능인지 구분된다. 첫·마지막 페이지와 총계를 독립 대조한다. 원본 전체 메시지나 개인정보를 Git에 올리지 않는다. UTC 경계·중복·누락 시각·페이지 재개를 검사한다.
모든 발견 소스에 완료/부분 완료/접근 불가 상태가 있고, 환경·중복 미확정 숫자를 서비스 오류율로 표시하지 않으면 통과한다.

## 중단·복구
읽기 부하 또는 쿼터 문제가 있으면 페이지 크기와 속도를 낮추고 커서부터 재개한다. 권한 불가 소스는 차단 사유를 기록한다. 기간을 축소해 전수 완료라고 주장하지 않는다. 운영 데이터 변경과 보관 설정 변경은 하지 않는다.
