# S17 — Sheets 기반 ‘이번 주 입금액 총액’ 독립 QA gate

2026-09-23. 읽기 전용 코드·계약 검토이며 실제 Sheets 호출이나 운영 데이터 검증은 수행하지 않았다. 주정산·월결산 파이프라인 변경은 범위 밖이다. 논문 원문 검토는 별도 연구와 합쳐야 하며, 본 문서는 논문을 읽었다는 주장을 하지 않는다.

## 먼저 고정해야 하는 업무 의미

1. **입금 범위:** `policies/cashflow-policy.json`의 IN 7개 라인에는 MYSC 선입금 3개, 매출액, 매출부가세, 팀지원금, 은행이자가 있다. 프로젝트 통장 유입 합계와 전사 외부고객 수금은 다르다. 내부 선입금·이체를 포함한 총액을 전사 순수 외부 유입이라고 표시하면 안 된다. 어떤 라인을 포함하는지 승인된 지표 정의에 기록한다.
2. **실적/예정:** Actual 입금행은 시트 38:44, 합계 45이고 Projection은 15:21, 합계 22다. ‘실제 입금’은 Actual이고 ‘입금 예정’은 Projection이다. 문맥으로 구분할 수 없다면 확인 질문 또는 적용 기준을 명시해야 한다. 서로 합산하지 않는다.
3. **이번 주:** Asia/Seoul의 오늘을 사용한다. 기존 `cashflow-week-core.mjs`는 월별 5개 정산 슬롯이며 달력상 6번째 주를 5주에 합친다. 첫 주는 월 시작일부터다. 달력 월요일~일요일과 동일하지 않을 수 있다. 정산주 집계만으로 날짜별 자료를 역산하거나 여러 달의 주차를 비율 배분해 달력주 합계를 만들 수 없다. 달력주 기준을 요구하면 날짜별 검증된 자료가 필요하다.
4. **모집단:** 권한 내 사본에 포함된 사업인지, 전체 활성사업인지, 정산 의무 대상인지 구별한다. 사업별 통화·원본 중복도 확인한다. 원화 아닌 값을 환산 정의 없이 합산하지 않는다.

## 읽어 확인한 실제 데이터 경로

- `server/bff/cashflow-coordinates.mjs`: A1:BT60, 주별 E:BL 60칸, 프로젝트당 단일 weeklyYear, 행 인덱스 LINE_ROWS가 유일한 라인 기준. C:D/BM:BR는 연간 값이며 주차 합산으로 대체하지 않는다. weekOrdinal=-1은 읽지 않는다.
- `docs/architecture/contracts/2026-07-28-cashflow-formula-validation-contract.md`: EMPTY/ZERO/VALUE/INVALID/ERROR를 구분하며 원 단위 정확 연산을 요구한다. Actual의 가변 SUMIFS 원천식을 새로 구현하지 않고 Sheets에서 계산된 결과를 고정 cashflow 블록에서 읽는다.
- `server/bff/google-sheets.mjs`: getSheetValues는 FORMATTED_VALUE, FORMATTED_STRING으로 요청한다. 현재 공용 client는 쓰기 가능한 spreadsheets scope 및 Firebase 서비스계정 fallback을 포함하므로 독립 readonly agent가 그대로 재사용하는 것은 별도 권한/격리 검토가 필요하다.
- `server/bff/cashflow-sheet-snapshot.mjs`: classifyModeCell이 Actual '-'는 ZERO, Projection '-'는 EMPTY로 보존한다. 일반 숫자 변환이나 `value || 0`로 대체하면 의미를 잃는다.
- `src/app/platform/cashflow-week-core.mjs`: 날짜의 월·정산주를 계산하고 6번째 달력주를 5번째 정산주로 묶는다.

추천 경로는 **독립 readonly 수집 → 고정양식 검사 → cell state와 원본 식별자·수집시각을 보존한 격리 사본 → 버전 고정된 입금 지표 정의 → 서버 계산 → evidence와 답변/HTML**이다. 기존 수집 사본을 재사용할 수 있으면 먼저 사용한다. 질문 실행 중 운영 sync/JVM fallback/제출·승인·마감 처리를 호출하지 않는다. Sheets API 읽기 자체도 quota·권한·운영 동시접근 영향을 가진다. 전용 자격증명과 quota/수집 빈도를 확정하기 전 ‘완전 격리됨’이라고 보고하지 않는다.

## 정확성 PASS 기준

- 해석한 기준(실적/예정, 입금 라인 집합, 정산주 날짜 범위, 통화, 대상 범위)을 계산에 쓰는 동일 정의에서 UI에 출력한다. 모델 설명과 실제 SQL이 서로 다른 기간을 가리키면 FAIL.
- 직접 입력 0과 Actual '-'는 0으로 인정하되 빈칸을 확인된 0으로 만들지 않는다. INVALID/ERROR/양식 불일치/주별 연도 밖 자료를 제외하고 완전한 합계라고 말하지 않는다.
- 7개 원천 행과 합계행을 동시에 더하지 않는다. 음수 정정·환입도 원본대로 유지한다. 합계 검증이 필요한 경우 원천행 합계와 고정 합계행을 대조하고 차이는 숨기지 않는다.
- 전사 합계는 대상 사업 수, 성공·실패·누락 사업 수, UNKNOWN/EMPTY 수, 통화와 시트별 수집시각 범위를 표시한다. 부분합이면 ‘확인된 N개 사업 부분합’이라고 표기하고, 누락을 0으로 채우지 않는다. 서로 다른 시트의 조회는 단일시점 원자적 스냅샷이 아니므로 최신성 범위를 드러낸다.
- 근거에 정의 ID/version, 원본 spreadsheet/sheet 식별자, 고정 셀 범위, mode, weeklyYear/yearMonth/weekNo, snapshot revision/hash, 수집시각, 적용 권한 범위를 남긴다. 모델이 직접 합계를 계산하거나 임의로 원본주소를 선택하지 않는다.
- 월/연도 경계, 6주 달, explicit zero/empty/error, 음수, 내부이체, 복수통화, 같은 sheet 중복 연결, 일부사업 API 실패·403·429, 수집 중 수정 및 권한 변경을 실제 fixture와 읽기 전용 통합에서 검증한다.
- 사용자 질의 정확도 평가는 정답 금액만 맞는지에 더해 적용 기간·mode·라인·모집단·누락 상태·근거 추적을 별도 채점한다. 잘못된 정의로 우연히 같은 숫자를 만든 경우 실패다. 모호한 질문에 확인 질문을 하는 것과 무조건 수치를 출력하는 것을 같은 성공으로 평가하지 않는다.

현재 판정은 **추가 가능하지만 업무 정의와 독립 데이터 연결 검증이 선행돼야 함**이다. API 연결 또는 문법이 맞는 SQL만으로 질의 정확성을 보장하지 않는다.

## 정확도 개선 기법에 대한 독립 제한

모델 자기반성, 여러 답변의 다수결, 자체 confidence 점수만으로 정답을 확정하지 않는다. 같은 잘못된 기간·입금 정의를 여러 번 사용하면 일치하는 오답이 생긴다. 피드백은 서버의 정의 검사, 실제 실행 결과, source cell 대조, 권한·완전성 검사에서 나온 구체적 실패에 한정해야 한다. 잘못된 plan을 고칠 기회를 주더라도 허용 지표·권한·기간을 임의 확장하지 않으며 시도 횟수와 비용 한도를 유지한다.

오프라인 평가의 정답은 모델에게 생성시키지 않고 검토된 고정 fixture로 마련한다. 최소 negative case는 다음과 같다.

| 입력/상태 | 허용 결과 | 실패 판정 |
|---|---|---|
| ‘이번 주 입금’이며 실적/예정 의미가 결정되지 않음 | 구체적인 기준 확인 또는 이미 확정된 대화 기준 적용 | 임의 기준을 숨기고 단일 총액 출력 |
| 달력주가 두 월에 걸침, 자료는 월별 정산주만 있음 | 날짜 단위 자료 부족 안내 | 주차 금액을 일수 비율로 나눠 추정 |
| 일부 사업 셀이 EMPTY/ERROR | 확인된 부분합과 누락 안내 또는 계산 보류 | 0으로 치환해 완전 총액 표시 |
| 후보 관련도가 높은 미허용 dataset/구버전 정의 | 실행 전 거부·허용 범위 내 재검색 | 후보 관련도로 권한·정의 검증 우회 |
| 동일 금액이지만 기간 또는 Actual/Projection이 잘못됨 | 평가 실패 | 숫자 일치만으로 성공 채점 |
| API 403/429/timeout 또는 권한 변경 | 제한된 재시도·부분합/실패 구분, 이전 화면 보존 | 운영 권한 확대·다른 자료로 조용히 fallback |

현재 허용 범위는 문서 설계·원문 연구·오프라인 fixture 평가 세트 준비다. 운영 Sheets 연동, 신규 서비스계정/권한·quota 확대, 모델 활성화 또는 주정산·월결산 변경은 수행하지 않는다. 실제 모델 평가도 아직 실행하지 않았다.

## 2026-09-23 구현 후 확인

사용자가 후속 오프라인 구현을 승인했다. 독립 native 계산 QA 11/11, 신규 실제 브라우저 흐름 2개를 포함한 전체 회귀 9/9 PASS다. 초기 timeCoverage 연결 누락과 숨김 CSS로 근거 표를 가릴 수 있는 문제를 발견했고, 실제 manifest 수정과 iframe 밖 앱 소유 근거 표시로 보완 후 다시 검증했다. 상세 범위와 미완료 운영 게이트는 [구현 기록](s17-sheets-implementation.md)을 따른다. 운영 Sheets 원본 진위·전사 대상 목록의 완전성·실제 모델 정확도는 이 PASS에 포함되지 않는다.
