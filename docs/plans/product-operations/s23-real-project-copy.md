# 실제 사업 DB 연결 검증 — 2026-09-28

## 데이터 경로

운영 Firestore의 `orgs/{tenant}/projects`를 읽기 전용으로 투영한 뒤, 별도 프로젝트의 사용자별 `axr_analytics/{scopeFingerprint}/datasets/projects_inventory_v1/versions/{contentHash}`에 불변 버전으로 저장한다. 사용자 모델은 승인된 표의 스키마와 해당 질문에 필요한 조회 결과만 받는다. 원본 읽기 계정은 앱 VM에 전달하지 않는다.

대상 사용자 한 명에게 데이터셋 하나를 명시적으로 연결한다. 관리자 역할만으로 모든 자료를 열지 않으며, 원본 회원 권한과 다른 구성원의 분석 권한을 변경하지 않는다. 자동 권한 복사가 다시 빈 목록으로 덮어쓰지 않도록 기존 복사 Job의 승인 grants 설정에 반영한다.

## 보존 및 조회 기준

- 원본 문서 ID와 저장된 사업 ID를 각각 보존한다. 중복·불일치를 병합하지 않는다.
- 사업명, 원문 상태, 조직, 계약기간, 종료 기간 없음 선택값, 수정 시각, 휴지통 이동 시각만 복사한다. 담당자·연락처·계좌·금액·첨부·자유서술은 제외한다.
- 휴지통 문서도 포함한다. 상태 코드나 휴지통 필드 부재로 활성·승인·정산 상태를 추정하지 않는다.
- 계약일의 빈 문자열과 누락은 원문 열에서 구분한다. 유효한 계약일만 별도 date 열로 조회하고, 날짜 형식 오류가 있으면 이전 사본을 유지한다.
- 단일 스냅샷을 최대 1,001건까지 읽으며 1,000건을 넘으면 부분 자료로 교체하지 않는다.
- `asOf`는 Firestore 조회 시각, `capturedAt`은 수집기 시각이다. 서로 다른 시계의 60초 이내 차이는 기존 분석 사본 기준과 동일하게 허용하며 시각 자체를 바꾸지 않는다. 문서 수정 시각은 나노초까지 조회 시각보다 늦을 수 없다.
- 이 자료는 등록 사업 문서의 사본이다. 임시저장·승인 요청·현금흐름·주정산·월결산 자료가 연결된 것을 뜻하지 않는다.

## 검증 기록

- 독립 QA 99/99 통과: 실제 합성 Firestore 저장·조회, DuckDB, 등록 API, 근거 재조회, 권한 회수, 원본 불변, 빈 문자열·NULL·false, 날짜 조건 자료형 검증.
- 실제 첫 수집은 원본/로컬 시계 약 1.65초 차이를 기존 1초 검사로 거부했다. 사본 쓰기 전 중단했으며 이 실패를 보존했다. 이후 공유 60초 허용 기준과 경계 회귀로 보완했다.
- 2026-09-28 실제 원본 80건을 독립 DB에 적재하고, 실제 DuckDB 조회로 80행을 다시 읽어 저장된 근거와 재조회 결과가 같음을 확인했다. 사본 버전은 `74a2682806ee191a35e22268ec193bb95ad52f159a93398bb7d8d6e83fefb94d`, 원본 조회 시각은 `2026-09-28T00:28:56.624249000Z`다. 계정·사업 원문은 공개하지 않는다.
- 첫 예약 갱신 뒤 해당 계정의 dataset 권한만 바뀌고 다른 28명의 권한은 그대로였다. 독립 QA가 80행 × 13열 전체 원문 일치와 예약 갱신 결과를 검증했다. [원문을 제외한 대조 결과](evidence/s23-project-copy-parity-0928.json)를 보존한다.
- 미리 정하지 않은 모델 질문 평가와 실제 사용자 로그인 UI 검증은 미완료다. 합성 테스트나 운영자 직접 조회를 모델 정확도·사용자 화면 성공으로 표시하지 않는다.
