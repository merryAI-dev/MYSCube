# S26 — MYSCube 실시간 읽기 API와 자동 화면 표시

## 요청과 실행 경계

사용자가 실시간 MYSCube API 연결과 ‘요청하면 화면이 바로 나오는’ 흐름을 승인했다. AXR 독립 앱만 수정한다. 기존 MYSCube BFF·JVM·주정산·월결산 처리 코드와 원본 DB 권한은 변경하지 않는다. 저장·버전 생성·Git 전달은 자동 화면 표시와 분리한다.

## 실시간 조회

고정 호스트 `https://myscube.myscguard.app`의 검토된 GET 두 개만 허용한다.

- `/api/v1/projects`: 한 번에 최대 20개. 기존 API가 제공하는 사업 항목을 허용 필드로 투영한다. 원본 문서 ID와 저장된 id의 구분, Firestore updateTime은 API가 제공하지 않으므로 null로 명시한다. 휴지통 문서도 포함하며 활성 사업 수를 추론하지 않는다.
- `/api/v1/cashflow-evidence`: 선택 월의 최대 10개 사업. API가 반환한 월·주차·기간·JVM 합계·누락·실패·다음 페이지를 보존한다. 이번 페이지 합계를 전사 합계로 표시하지 않으며, JVM 조회 시각과 실제 Google Sheets 최신성은 구분한다.

사용자가 이미 로그인한 Firebase 인증을 검증한 뒤 서버 메모리에서만 최대 60초·원본 토큰 만료까지 위임한다. 각 API 호출 전 인증을 다시 검증한다. 같은 계정·조직·권한 범위의 새 검증 요청만 갱신할 수 있다. 토큰은 생성 코드·모델·원격 렌더러 IPC·DB·응답·로그에 넣지 않는다. 별도 DB 서비스 계정이나 정적 운영 인증키를 만들지 않는다.

공개 DNS 검증·고정 IP 연결·리디렉션 차단·10초 제한·256KB 응답 한도를 적용한다. 전체 동시 2개, 사용자별 1개, 분당 전체 60회/사용자별 12회이며 대기열은 만들지 않는다. 종료되지 않은 소켓의 자리도 성급히 반환하지 않는다. 현금흐름 요청 실패·취소 시에는 소켓 종료와 원본의 알려진 25초 조회 예산이 모두 지난 뒤 자리를 반환한다. 원본 BFF가 연결 종료와 작업 취소를 연결하지 않는 점을 고려한 것이며, 원본 작업이 즉시 취소됐다는 보장은 아니다. 사용자의 월/페이지 변경·수동 갱신에 따라 조회하며 자동 폴링·전체 페이지 자동 순회는 생성 지침에서 금지한다.

인증된 운영 앱에서 활성화하고 `WORKBENCH_MYSCUBE_LIVE_ENABLED=false`로 중지할 수 있다. 헤더 기반 에뮬레이터 모드에는 자동 활성화하지 않는다. API 등록·소유자·불변 버전·중지 규칙은 기존 등록 서비스를 사용한다.

## 대화와 실제 실행의 근거 일치

대화 조회와 생성 화면의 API 호출 모두 같은 등록 API 서비스에서 실제 응답 근거를 저장한다. API ID·버전·정의 해시·endpoint 해시·입력 조건·자료 시각·범위를 남긴다. 생성 전 연결 검사와 화면 실행 후 근거 비교가 같은 식별자를 사용한다. HTTP 근거 조회에서도 이 항목이 누락되지 않게 한다. 실시간 자료를 사본 SQL 결과로 위장하지 않는다.

## 자동 표시

새 생성·후속 수정의 검증된 최신 응답만 편집본과 실행 후보에 원자적으로 반영한다. 사용자가 요청 중 파일·제목·API·대상을 바꾸면 늦은 결과가 덮어쓰지 않는다. 새 실행이 성공해야 마지막 정상 화면을 교체한다. 실패 시 마지막 정상 화면을 유지하고 오류를 안내한다. 기존 대화를 다시 열거나 재전송 응답을 받은 것만으로 다시 실행하지 않는다.

빈 새 화면에서 등록된 실시간 API `myscube-projects`·`myscube-cashflow-evidence` v1을 기본 선택한다. 사용자의 명시적 연결 해제, 기존 저장 화면과 복구·대화 문맥은 덮어쓰지 않는다.

## 검증 범위

독립 QA는 실제 HTTP 인증 경로·Firestore 등록/불변 버전·실제 어댑터(상류 통신만 합성)·원격 콜백·HTTP 근거 조회를 검증한다. 권한 회수·토큰 교체·누락과 0·월 변경·응답 누락·실행 실패를 반증한다. 자동 표시 브라우저 검사는 실제 컴파일러와 React 실행을 포함한다.

2026-09-28 구현 중 운영 AXR VM에서 인증 없는 두 MYSCube API 요청을 확인했고 모두 HTTP 403이었다. 로컬 응답의 Cloudflare 차단 제목·본문도 확인했다. AXR 서버 IP 34.64.247.190의 정확한 GET 두 경로에 대한 접근 규칙 조정 여부를 사용자에게 확인 중이다. 사용자 인증을 우회하거나 일반 경로 전체를 허용하지 않는다. 이는 로그인한 사용자 요청 성공의 증거가 아니다. 실제 로그인 인증을 전달한 운영 조회는 별도 수용 항목이며 검증 전 완료로 표시하지 않는다. 새로운 배포·등록·최종 테스트 결과는 아래에 기록한다.

## 검증 기록

- 독립 QA: HTTP·어댑터·기존 외부 API 34/34, 자동 표시·실행 교체 브라우저 18/18, 저장된 실제 조회 근거 브라우저 2/2 통과. 상류 응답은 합성 자료이며 운영 로그인 조회 성공을 뜻하지 않는다.
- 전체 브라우저 회귀: 94/94 통과 (`/tmp/myscube-s26-browser-full.log`).
- TypeScript 검사와 production build 통과. 기존 500KB 청크 경고는 남아 있다.
- 전체 서버 회귀 첫 실행: 1,246 통과·1 실패·7 제외. 대화 API 메타데이터가 컴파일 캐시에 중복 컴파일을 유발하는 실패를 발견했다. 컴파일과 무관한 최상위 근거 해시 두 개만 정규화했으며 실제 API 정의·응답 스키마·사용자 권한별 분리는 유지했다. 독립 QA 18/18, 실제 대화→실행→저장 포함 관련 22/22 통과.
- 배포 전 독립 DB 확인: 저장 화면 3개, 버전 183개. 원본 서비스 데이터는 수정하지 않았다.
- 최종 전체 서버 회귀: **1,248 통과·7 제외**, 116 파일 통과 (`/tmp/myscube-s26-full-tests-final.log`). 제외 7개는 별도 브라우저 실행 조건의 기존 컴파일러 테스트이며 전체 UI 브라우저 94개는 별도로 통과했다.
- 독립 QA 최종 구현 게이트 PASS. 운영 실시간 조회 성공은 Cloudflare·로그인 검증이 남아 있어 이 판정에 포함하지 않는다.
