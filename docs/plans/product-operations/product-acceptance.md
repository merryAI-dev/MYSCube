# 제품 완성 목표와 추가 기능

2026-09-22 사용자 지시: API 키 설정을 제외하고 실제 제품 수준까지 계속 개발한다. 이어서 개인별 임시 업무 페이지와 전사 현금흐름 근거 기반 에이전트 기능을 포함한다. 두 기능은 기존 품질 운영 도구와 같은 권한·API 계약을 사용한다.

## 완료 기준

1. 품질 운영: 실제 저장·제출·승인 시도와 서버 저장 결과를 연결하고, 관리자 화면에서 집계·사건·수정 이력을 조회·관리한다. 구성원은 공개된 원인·다음 행동을 확인한다.
2. 개인 업무 페이지: 사용자별 페이지 구성·버전 저장·다시 열기·복원·삭제를 제공한다. 표·요약·필터를 등록된 읽기 API에 연결한다. 자연어 생성은 모델 설정이 있을 때 활성화하며, 설정 없이도 구성과 미리보기·버전 관리가 동작한다.
3. 현금흐름 에이전트: 현재 권한으로 조회한 실제 금액·수집 상태·진단 로그와 검토된 코드 근거를 연결한다. 확인된 사실·원인 후보·미확인 사항을 구별하고 조회 시각·사업 범위·근거 ID·코드 버전을 표시한다. 자연어 모델 키가 없으면 명시적 조회/진단 도구와 근거 화면을 제공하고 AI 답변을 생성했다고 가장하지 않는다.
4. UI는 관리자와 실무자 동선에 연결하고 모바일·빈 상태·권한 거부·로딩·연결 오류를 검증한다. 저장·재조회·타 계정 격리·이전 버전 복원을 실제 API와 저장소에서 대조한다.

## 변하지 않는 범위

주정산·월결산 처리, 캐시플로 고정 좌표 계약, 운영 초안·결재 자료를 변경하지 않는다. 새로운 화면에서 기존 사용자의 데이터 권한을 넓히지 않는다. 에이전트는 운영 데이터를 수정하거나 임의 쉘·SQL·URL을 실행하지 않는다. API 키나 서버 비밀값을 페이지 코드 또는 브라우저에 넣지 않는다.

TOI의 임시 화면 생성 개념은 우선 검증 가능한 페이지 구성 스키마와 기존 React 컴포넌트에 적용한다. 임의 코드 실행·패키지 설치·브라우저 번들러 자체 개발은 별도 실행 격리가 검증되기 전 활성화하지 않는다. 생성된 화면은 데이터 권한과 서버 검증을 우회할 수 없다.

## 확인한 공개 구현과 반영점

- 사용자 제공 토스 「AI가 만든 코드가 어드민이 되기까지」: 플랫폼이 API 정책과 실행 환경을 보장하고 화면을 분리하는 원칙. 사용자별 격리·검증된 버전 유지·미리 준비한 구성 요소를 적용한다. TOI의 성능 수치를 MYSCube 측정값으로 사용하지 않는다.
- [Sentry의 Group 모델](https://github.com/getsentry/sentry/blob/master/src/sentry/models/group.py): 사건 상태와 발생 이력을 분리해 관리하는 참고. MYSCube에서는 담당자·원인 근거·조치·공개 문구와 변경 이력을 유지한다.
- [OpenTelemetry exporterhelper](https://github.com/open-telemetry/opentelemetry-collector/blob/main/exporter/exporterhelper/README.md): 큐 수용 실패와 재시도는 서로 다른 실패 경로다. 계측 실패를 업무 실패와 분리하고 수집 완전성을 과장하지 않는다.
- [ToolJet query permissions](https://docs.tooljet.ai/docs/app-builder/connecting-with-data-sources/creating-managing-queries/): 페이지 접근과 조회 실행 권한을 별도로 검사한다. 개인 페이지에도 기존 서버 권한을 적용한다.
- [Appsmith 보안 문서](https://github.com/appsmithorg/appsmith-docs/blob/main/website/docs/product/security.md): 클라이언트 코드는 열람 가능하므로 비밀값을 넣지 않는다. 화면 격리만으로 데이터 권한이 보장된다고 가정하지 않는다.

코드·문서는 참고하되 라이선스 검토 없이 외부 구현을 복사하거나 서비스 의존성을 추가하지 않는다.
