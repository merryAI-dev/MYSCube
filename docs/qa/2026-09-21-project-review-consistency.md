# 프로젝트 최종 제출·승인 문서 정합성

## 범위와 원칙

실무자의 등록/수정 임시저장과 최종 제출, 관리자의 승인 문서 사이 정합성을 수정한다. 임시저장은 소유자 작업본, request payload/proposedSnapshot은 해당 제출본, project는 승인 반영 원장이다. 결재 문서의 업무 필드는 요청 종류와 승인 상태에 관계없이 해당 제출본에서 읽는다. 요청이 없는 원장 검토만 project를 읽는다. 누락/null을 현재 원장이나 비공개 임시저장으로 채우지 않는다.

권한, 승인 상태 전이, 낙관적 버전 검증, 멱등 처리, draft 정리 시점은 변경하지 않는다. 운영 데이터 수정/마이그레이션 없음. 50MB 확대, 날짜 기반 상태 자동 변경, 금액 불일치 신규 차단, 정산 프로세스 개편은 별도 범위다.

## 확인한 원인과 조치

| 원인 | 조치 |
|---|---|
| dossier는 등록/수정 및 대기/승인 여부에 따라 project와 request 필드를 혼합했다. 문서 본문은 request인데 체크아웃 노출은 project.status였다. | 본문·기안부서·계약서·체크아웃 노출을 제출본 기준으로 통일. 제출 이후 임시저장은 결재 문서에 포함되지 않는다고 안내. |
| final_report 업로드 경로는 있었지만 client payload/patch 및 BFF 신뢰 첨부 목록·snapshot·승인 patch·요청 첨부 조회 매핑이 빠졌다. | 누락된 매핑 연결. 과거 요청에 해당 필드 자체가 없으면 승인 때 기존 원장 첨부를 보존하며 명시 null은 제거로 처리. |
| 제안서 PDF 및 종료 증빙 4종이 승인 문서 슬롯/미리보기에서 빠졌다. 파일이 있으면 함께 제출한 Drive 링크가 가려졌다. | 실제 제출된 추가 문서를 표시하고 파일과 링크를 함께 제공. 기본 제출서류 7종의 필수/선택 정책은 유지. |
| 실무자 다년도 입금 요약은 연도별 합계, 관리자 요약은 최상위 paymentPlan이었다. | 공통 읽기 전용 계산으로 다년도 합계를 사용. 단년도는 기존 top-level 계획. 연도별 0원 분모를 전체 계약금액으로 대체하지 않음. |

매핑 누락은 여러 whitelist가 독립적으로 관리되어 발생했다. 이번에는 경로별 누락을 좁게 연결하고 제출 snapshot 선택 및 입금 계산을 통일했다. 전체 필드 registry 도입이나 BFF 교체는 하지 않았다. 변경 경로는 UI draft → client payload → BFF trusted attachments → request snapshot → review document/attachment GET → approval patch → project read이다.

## 운영 읽기 증거와 한계

2026-09-21 읽기 전용 수집에서 프로젝트 79개(미휴지통 71), 요청 125개(승인 87/대기 28/반려 9/회수 1), privateEditDrafts 66개, projectRequestDrafts 167개, legacy projectRequests 0개를 확인했다. 다섯 collection 모두 페이지 조회 완료; project/request 재조회 updateTime 차이 없음. 원문은 개인정보·문서 참조를 포함하므로 저장소에 넣지 않았다.

- JLIN 실제 제출본의 5개 연도별 선금 합계는 24.5억/총계약 35억=70%, 최상위 선금 4.9억/35억=14%였다. 같은 저장값의 표시 경로 차이를 재현하는 회귀 fixture를 사용한다.
- KDB 원장과 제출본 모두 COMPLETED였다. 이번 snapshot 정렬이 과거 잘못 저장된 상태를 자동 복구한다고 주장하지 않는다.
- 농산업 계약금액 1.2억과 구성항목 합계 4,800만원 불일치는 제출본에도 존재했다. 표시 수정과 별도의 입력 정책 사안이다.
- 탐나는인재는 유사명 프로젝트가 복수 존재하며 Sep17 요청은 링크 없음, Sep18 요청은 두 링크 존재였다. 이름만으로 링크 유실을 단정하지 않는다.
- finalReportDocument는 원장 1개, 요청 0개였으나 제출된 draft의 payload가 정리되어 과거 파일 유실을 확정할 수 없다. 매핑 위험과 재현 테스트를 근거로 수정한다.

이 조사는 저장 데이터의 전수 읽기와 코드 계보를 결합한 것이며 모든 운영 프로젝트에 대한 사용자 브라우저 조작이나 과거 임시저장 유실 0건을 증명한 것은 아니다. 테스트의 승인/저장은 격리 fixture·에뮬레이터에만 수행한다.
