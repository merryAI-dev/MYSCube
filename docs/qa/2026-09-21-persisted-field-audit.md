## 확장 QA 게이트

1. 자료 gate: 전체 조회와 분모/요청 선택/누락 정의 — 이번 스냅샷에 한해 완료.
2. 필드 계보 gate: 123개 필드 중 업무 입력과 서버 관리 필드를 분류하고 각 제출→승인→표시 규칙을 확인 — 핵심 업무 경로만 구현 검증됨; 모든 필드의 의미 검증 완료 아님.
3. 시각 gate: 프로젝트별 선택된 제출본과 실제 렌더 결과를 비교하고 숨김/누락/표시값 불일치를 기록 — 별도 시각 감사 결과 필요. 저장 JSON 비교로 대체하지 않음.
4. 보존 gate: 과거 제출 직전 원문과 제출 후 snapshot 대조 — payload 정리로 현재 자료만으로 불가. 새 경로는 격리 BFF lifecycle 검증으로 제한.
5. 운영 해결 gate: 사용자 사례의 표시 수정과 저장 데이터/정책 문제를 각각 판정 — KDB 상태와 농산업 금액 문제는 이번 패치로 해결했다고 주장하지 않음.

운영 데이터, 업로드 파일, 권한, 결재 상태를 수정하지 않았다. 제품 코드 수정도 없다.

## 결재 도장·이력 선택 추가 감사

JLIN 화면의 최신 결재 날짜(9월 17일)와 메모 날짜(5월 31일)가 다른 이유를 별도 확인했다. 원장 현재 결재자/시각, 같은 상태의 마지막 history, 최신 승인 CHANGE의 결재자/시각은 모두 일치했다. 9월 17일 승인에는 메모가 없고 5월 31일 과거 승인에는 메모가 있다. dialog는 `reviewMessages`에서 메모 없는 이력을 제외하므로 과거 메모만 보인다. 이 사례는 **최신 history 선택 오류로 확인되지 않았다.** 현재 결재와 이전 메모를 같은 사건으로 읽게 되는 표시 혼동 가능성은 남는다.

전79개 원장 중 결정 상태(APPROVED/REVISION_REJECTED/DUPLICATE_DISCARDED) 61개 모두 해당 상태 history가 있었다. 현재 결재자 이름과 reverse/find가 선택한 history 이름의 차이 0개, 날짜 차이 0개, 선택 행과 시간상 최신 동일상태 행의 차이 0개였다. 비교는 현재 원장 기준이며 과거 요청별 결재 이력이 완전하게 분리되는지를 증명하지 않는다. 표시된 기안자와 결재자가 같다는 사실만으로 권한 위반을 추론하지 않는다.
