### 농산업의 직접 증거

프로젝트 `p1774869407448`, 요청 `change-p1774869407448`, 승인완료 요청v1, 원장v7.

- 계약120,000,000, 수익48,000,000, 원가0, 지원금0.
- 상위 `financialInputFlags.totalActualCost=false`, `supportAmount=false`.
- 저장된 2026년 행에는 `inputFlags` 자체가 없다. 따라서 저장된0을 명시적0원 입력으로 확정할 수 없다.
- 입력 화면은 원가·지원금 공란과 필수 안내를 표시하지만 승인 연도표는0원으로 표시한다.
- 추가 표시 문제: 보존한 계약120,000,000 밑에 **계산됨**이 표시되지만 현재 입력된 구성 항목 소계는48,000,000이다. 레거시 계약금액 보존과 현재 항목 합산 완료를 구분하는 안내가 필요하다.
- 금액을 자동 보정하거나72,000,000원을 원가로 확정하면 안 된다. 위72,000,000은 입력 동작 검증용 격리 값이다.

## 필요한 후속 조치

1. 승인 연도별 재무 표·총계·입금계획 표시에도 입력 상태를 전달하고, 명시적0원과 미입력을 구분한다. 구형 행에 플래그가 없으면0원을 임의로 입력 완료 처리하지 않는다.
2. 단년도 기존 계약금액을 보존하는 경우 ‘계산됨’ 대신 보존값/입력 미완료 여부를 명확히 표시한다.
3. KDB는 최신 저장 상태가 왜종료인지 이력을 조사하고 실제 진행 상태를 확인한다. 화면 조건만 바꿔 상태 불일치를 가리지 않는다. 주정산·월결산에는 손대지 않는다.
4. 과거 미입력 문서를 현행 검증을 통과한 문서처럼 표시하지 않는다. 기존 값은 유지하고 작성자의 명시적 보완 후 재제출하도록 안내한다.

따라서 **모든 불일치가 해소되었다는 판정은 FAIL**이다. 숫자 입력 및 JLIN 비율 문제의 현재 재현 결과는 PASS지만, 구형 저장본의 미입력/0원 표시 일관성과 KDB의 저장 상태 적정성은 남아 있다.

## 후속 수정 후보의 재검증 — 아직 배포 판정과 별개

위 배포본 실패를 근거로 공유 표시 로직·승인 연도표·dossier를 수정한 작업 트리를 격리 검증했다. 원장 값·제출 값은 변경하지 않았다.

- 명시적 입력 플래그 true인0원은0원, false는미입력, 과거0원인데 플래그가 없으면입력 기록 없음으로 표시.
- 양수 저장값인데 플래그false인 경우 `미확인 (저장값 …원)`으로 보존 표시.
- 연도별 금액 입력 상태는 연도별 행 자체의 증거만 사용한다. 상위 합계의 입력 완료 상태를 연도별0원에 전파하지 않는다. 단년도 입금계획 값과 그 값에 해당하는 입력 플래그만 같은 원본에서 함께 투영한다.
- 다년도 입금 합계는 각 연도의 입력 근거를 확인한 경우만 확정 합계로 표시한다. 누락을0원으로 합산하지 않는다.
- 미완성 합계용 공유 formatter는 `합계 미완료 (확인된 소계 …)`를 제공한다. Wizard 연결 검증은 담당 루트의 별도 결과와 합친다.

표시 로직·실제 승인 표·상세 패널·dossier 테스트 **32/32 통과**. 최신 운영 읽기 스냅샷 농산업/JLIN/모비스를 실제 승인 컴포넌트에서 재렌더하고 DOM 검증했다. 농산업 원가·지원금은연도별 입력 기록 없음, 모비스 구형0은입력 기록 없음, JLIN 선금합계2,450,000,000원(70%) 보존을 확인했다. 브라우저 오류0개.
