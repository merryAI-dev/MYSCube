# 모바일 홈 진입 및 명함 DB 화면 제거

## 원인과 변경

관리자 공간 버튼은 `/`로 이동했으나, 루트 페이지가 모바일 UA/화면 폭에 따라 명함 DB를 렌더링했다. 로그인 완료 경로와 설치 앱 `/mobile-entry`도 같은 기능을 기본 화면으로 사용했다.

- 관리자 루트를 기기 구분 없이 기존 Feature Search 홈으로 통일.
- 로그인 완료 경로에서 모바일 명함 전환을 제거. 기존 역할/작업공간별 홈 유지.
- 설치 앱 경로는 인증 확인 후 해당 홈으로 이동. 기존 설치 앱 start_url 유지.
- 명함 UI 컴포넌트, 메뉴/검색 후보, LAB 목록, PWA 바로가기와 설치 안내의 명함 문구 제거.
- 이전 `/business-cards`, `/portal/business-cards` 링크는 인증/역할별 홈으로 치환.
- 기존 명함 자료, BFF 명함 API 및 데이터 보관 코드는 유지. 운영 데이터 삭제나 보안 규칙 변경 없음.
- JVM·주정산·월결산·프로젝트 임시저장·승인 처리 변경 없음.

## 검증

- 진입 관련 최초 테스트 60개 통과.
- 전체 테스트 4,483개 통과 중 변경된 내비게이션 정책의 기존 기대값 1개 실패. 실제 정책은 알 수 없는 경로를 NotFound/호환 경로 처리에 맡기므로, 퇴역 메뉴의 권한 제거 검증으로 고쳤다. 해당 파일 13개 재실행 통과.
- 신규 타입 오류 없음. 빌드와 PWA 패키지 검증 통과.
- 독립 QA는 실제 로그인/설치앱 페이지, production router의 관리자 루트, WorkspaceSelectPage 클릭을 모바일/데스크톱에서 검증한다. 인증과 store만 합성 fixture이며 운영 데이터 쓰기는 하지 않는다.

독립 브라우저 최종 37사례 통과: 설치앱/로그인 20, 이전 명함 URL 12, 설치 안내 3, 관리자 공간 클릭 2. 명함 화면 노출 0, 브라우저 오류 0. 모바일 실제 홈 캡처를 육안 확인했다. 근거: `/tmp/myscube-presentation-qa/evidence/mobile-home-qa.json`, `removed-card-qa.json`, `workspace-home-qa.json`. 캡처: `assets/mobile-home/admin-home.png`.
