## 단계별 종료 조건과 미완료 범위

1. **자료 범위 확인 — 완료(해당 시점).** 79개 ID 전부 목록화, 요청 없는5개와 휴지통8개 포함. 이력125개를 수집했지만 본 표의 차이 집계는 최신 요청 기준이다.
2. **원인 분류 — 부분 완료.** UI 슬롯/원본 혼합/분모/외화 단위는 소스와 표시 증거로 좁혔다. 금액·반납·이월금·종료상태의 업무상 정답은 미확정이다. 테스트 사업은 실제 사용자 사고 건수와 분리한다.
3. **구현 검증 — 별도 패치 범위만.** 제안서/종료첨부·파일과링크·제출본 표시 변경의 회귀 검증을 전체79개 해결로 확장하지 않는다. 종료일없음 false 해제, 링크 명시삭제, 예산 재설정 등 BFF 추가 재현은 공통 위험이며 이 표에서 해당 사업 피해를 추정하지 않는다.
4. **시각 검증 — 운영71문서 본문 열람 완료/전 입력화면 대조 미완료.** 스크린샷 대표확인과 DOM 본문열람을 구분한다. 브라우저 연결 중단 이후 추가 픽셀 대조는 재연결 또는 실제 제출본의 읽기 전용 재현 증거가 필요하다.
5. **정산·결재 회귀 — 미완료.** 종료 체크아웃은 주정산/월결산 정본과 읽기 전용 연결 검증이 필요하다. 최종 대상월을 계약종료월로 단정하지 않고 잔금·비용처리월을 확인한다. 신규 종료권한·자동승인·자동월결산을 만들지 않는다.
6. **운영 완료 판정 — 보류.** 원본 금액/업무상태 확인, 의도한 표시 수정, API 왕복 보존, 배포 SHA·운영 재조회 증거가 필요하다. 이번 감사에서 운영 데이터 보정은 하지 않았다.
