# 등록·수정 필수값 전수조사와 조치안

2026-09-21. 사용자가 지정한 정책은 **선택으로 표시된 항목 외에는 필수**다. 실제 적용 여부가 없는 조건부 항목, 자동 계산·시스템 관리값을 수동 필수 입력으로 바꾸라는 의미로 확장하지 않는다. 현재 구현의 공란 허용을 업무상 선택이라고 간주하지 않는다.

## 수정 전 조사 결론

사용자 실수가 아니라 입력 상태와 최종 제출 검증의 시스템 결함이다. 이전 배포는 제출·승인 표시와 버전 일치를 개선했으나, 필수 입력 완전성까지 보장하지 못했다. 이번 전수조사로 그 한계를 확인했다. 원가가 없는 제출을 지금 모두 해결했다고 선언할 수 없다.

1. 연도별 입력은 공란을 0으로 변환하고 0을 항상 표시한다.
2. 표의 항목 하나를 바꾸면 VAT·수익·원가·지원금 등 5개 입력 완료 상태를 모두 true로 만든다.
3. 화면 제출 검사는 연도 존재와 전체 합계만 검사한다. 각 금액을 실제 입력했는지 확인하지 않는다.
4. 서버는 계약금액 외 금액의 undefined/null을 허용하고 저장 문서를 만들 때 0으로 바꾼다. 단년도에서는 연도별 배열 검증도 생략된다.
5. 다년도 검사도 연도합과 전체금액의 동일성 중심이며 계약금액과 VAT+수익+원가+지원금 구성합 일치까지 검증하지 않는다.

따라서 화면과 승인 문서가 동일하게 0원을 보여도, 사용자가 원가 0원을 입력했다는 증거가 되지 않는다.

## 증거

- 실제 Wizard 브라우저: 원가를 건드리지 않고 수익만 입력했는데 저장 콜백의 원가가 0, 입력완료 true. `/tmp/myscube-interest-browser/finance-empty.json`, `finance-empty.png`.
- 실제 BFF canonical builder 47개 조합/필드 삭제 재현: 원가 undefined/null도 제출 문서 생성 성공. VAT·수익·원가·지원금 모두 누락해도 계약금액 300,000, 구성합 0으로 성공. 음수는 거부되므로 수치 범위 검사와 필수 검사가 분리되어 있음을 확인.
- 운영 DB 재조회: 한국시간 2026-09-21 14:35:47~14:35:54, 프로젝트 79개·요청 125개·임시저장 235개 전체 페이지 읽기. 최신 제출본이 있는 프로젝트 74개 중 원가 키 없음 28개, 원가0 19개. 원가 입력 플래그는 false11/true35/없음28. **과거 형식·휴지통 포함이며 현재 오류 건수로 단정하지 않는다.**

## 수정 순서와 수용 기준

1. **금액의 입력 상태 분리:** 연도·필드별로 공란/명시0/수치를 보존. 다른 셀 수정이 원가 입력상태를 변경하지 않게 한다. 초안 저장·재열기에서도 동일 상태여야 한다.
2. **필수 계약 공유:** 화면 required, 단계별 오류, 최종 제출 BFF가 같은 필드/적용 조건을 사용. 숫자0과 boolean false는 값으로 인정하며 빈값은 누락으로 판정한다. 선택 항목은 그대로 선택이다.
3. **제출 경로 통일:** 신규·수정뿐 아니라 직접 프로젝트 쓰기 API에도 허용 목적과 권한을 확인한다. 초기 원장 생성·관리자 운영 수정까지 무조건 같은 규칙을 적용하지 말고, 최종 제출을 우회할 수 없음을 입증한다.
4. **불변 제출본과 과거 호환:** 새 최종 제출에 필수 검증 적용. 과거 문서는 누락을 명시하고 저장본을 자동 수정하지 않는다. 기존 승인 요청에 새 필수 규칙을 소급해 일괄 차단하지 않는다.
5. **실제 경로 검증:** 연도별 각 필드 삭제/공란/null/0, 단년/다년, 임시저장·재열기·최종제출·승인조회, 선택/조건부 분기를 UI와 실제 BFF에서 각각 검증한다. 필수 검사를 제거하면 테스트가 실패해야 한다.

이자 반납 필수 및 사업비 입력 방식 읽기전용 노출 수정은 작업 트리에 있으며 미배포다. 관련 BFF 270개 테스트와 브라우저 6건, 빌드 통과. 전체 필수값 개선이 완료된 상태는 아니므로 이 소규모 변경을 전체 해결로 안내하지 않는다. 운영 데이터 변경 및 주정산·월결산 파이프라인 변경은 없다.

## 이번 구현 경계 (미배포)

화면에서 제출하는 등록·정보 수정 경로는 공유 필수 정책을 사용한다. 표시되는 입력값은 필수 또는 명시적 해당 없음 응답을 요구하고, 조건부 입력은 해당 조건에서만 요구한다. 금액 공란과 직접 입력한 0을 구분하며 연도별 입력 상태와 입금 계획 입력 상태를 제출 스냅샷에 보존한다. 첨부 4~7번도 제출/링크 또는 명시적 해당 없음·기존 미첨부 사유가 있어야 한다. 미완료 상태의 임시저장은 허용한다.

자동 계산·숨겨진 구형 필드·시스템 식별값은 수동 필수 입력으로 추가하지 않는다. 참여율의 빈 명단은 연결된 시트의 검증 결과를 따른다. 이미 제출한 구형 요청의 승인에 새 필수 정책을 소급 적용하지 않는다. 기존 운영용 직접 projects upsert는 주정산·월결산 호출과 섞여 있어 이번 차단 대상에서 제외했다. 따라서 플랫폼의 모든 쓰기 API가 새 정책으로 통일됐다고 볼 수 없으며, 후속 분리안은 `docs/architecture/proposals/2026-09-21-project-direct-write-approval-boundary.md`에 기록했다.
