# 프로젝트 제출·임시저장·승인 정합성: 배포 전 검증

작성: 2026-09-21. 운영 데이터 쓰기, 승인 실행, main 머지, 배포는 하지 않았다.

## 범위

주정산·월결산 계산, 동기화, 확정, 잠금 및 캐시플로 좌표 계약은 변경하지 않았다. 독립 QA가 변경 파일과 projects.mjs의 기존 참여인력 동기화 구현·호출부를 대조했다. 승인 후 budgetCurrentYear=777 및 settlementLocked=true 보존을 실제 승인 handler 테스트로 확인했다. 제출 문서의 정산 관련 입력 필드 표시·누락 보존은 이 파이프라인 변경과 구별한다.

## 변경 및 증거

| 항목 | 구현과 검증 |
|---|---|
| 임시저장 | 최종 제출용 변환과 분리한 초안 serializer. 실제 Wizard·재열기 함수·초안 service fixture를 연결하여 늦은 저장 응답 이후 입력 유지, 재저장, 로컬 캐시 제거 후 서버 초안 재열기를 확인했다. 첨부 참조와 revision 유지. |
| 제출 소유 필드 | 프론트와 BFF가 공통 필드 계약을 사용. 알 수 없는 제출 키를 조용히 버리지 않고 거부. 과거 본문의 누락은 기존 원장 보존으로 처리. false, 빈 폴더 링크, null 첨부 등 명시적 변경을 테스트했다. |
| 실제 왕복 | 수정 초안→제출→검토 GET→승인→원장 조회에서 종료 기간 없음 해제, 종료일, 폴더 비움, 첨부 및 운영 예산 보존을 검증했다. |
| 승인 버전 | 검토 GET이 프로젝트와 요청을 transaction으로 읽어 토큰 반환. 승인 transaction에서 동일 내용 검증. 같은 버전 번호라도 본문이 바뀌면 409. 가드를 제거한 사보타주 실험에서는 기대한 테스트 실패를 확인했다. |
| 구형 문서 안내 | 이전 형식 자체는 경고만 표시. 실제 첨부 발행·저장 객체·요청 버전 검증 실패는 항목별 원인과 조치로 표시. 차단 사유가 있으면 승인 버튼은 비활성화하며 반려는 유지한다. |
| 재검토 | 실제 React 승인 화면에서 변경 충돌→의견 유지→명시적 문서 재조회→새 토큰 승인 흐름을 API mock으로 검증했다. 자동 승인 재시도는 없다. |
| 양쪽 표시 | 저장된 연도별 VAT·수익률·확인 상태, 참여인력 월별 값, 폴더, 입금계획을 공통 표시 함수로 정렬. 79개 저장 자료의 입력 4단계와 승인 문서 대조 결과는 별도 화면 보고서에 기록했다. |

검증 중 담당자 alias 누락, 테스트 환경 git 초기화 누락, 신규 테스트 파일의 선언 없는 JS import, 수정 왕복 fixture의 참여율 링크 누락을 발견했다. 원인별 코드 또는 검증 환경을 수정한 뒤 재실행했다.
